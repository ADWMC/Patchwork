# 2026-11-01 闭环补全与验收

本文对应全仓审查的 24 项缺口，记录当前实现、入口及证据。旧调研、原评测失败和私人会话的边界继续保留；当前版本仍为 0.2.0 的未发布改动。机器验收不等于模型质量提升。

## 实际用户路径

1. 在当前会话切换到 Patchwork。普通 Agent 不能看到工具、面板数据、记忆或改进；独立浏览器仍需另外安装并按会话授权。
2. 实际工具失败、浏览器后验不匹配、用户纠正会产生有来源的 Incident；“证据 → 改进”展示触发、来源和候选。自由文本提议不会执行。
3. 对受限 typed patch 运行隔离实验。两个新 Node 进程分别执行 baseline/candidate，使用 runner 固定的调优与留出用例；证据绑定会话、候选版本、来源和 SHA256。任意自填的 real-host 成绩不被接纳。
4. 查看范围、差异、退化、副作用与证据后，用户点击“确认试用/确认应用”。只有 `applied:true` 表示本会话策略实际启用；无确认、过期或改动证据、旧 revision 均拒绝。项目全局应用不开放，接收会话各自确认。
5. 点击“回滚此改动”实际移除此候选，恢复此前策略。切换 Agent/销毁也撤销；重启后不自动应用，隔离实验需重新签发。

| 对象 | 受限改动 | 实际消费者 |
| --- | --- | --- |
| rule | verifyBeforeDelivery=true | 有任务时的 pre-step 交付复核提醒 |
| memory-policy | recallLimit=1..5 | 按需记忆召回上限；不改动已存记录 |
| tool-flow | requireCrossCheck=true | 引用前必须有两个已发送 JSON 摘录的 supported 字段比较 |
| ui-copy | reviewDetail=compact/full | 改进页审核提示与详情默认展开状态 |

这里的实验是 **policy-contract**，没有训练模型、自动改代码、写任意提示词或更改权限。它验证受限运行行为与隔离，不是基于模型回答的调优/泛化试验；模型、token 和付费成本未测，不能宣传收益率。

## 验收边界

默认回归含纯逻辑、故障注入、真实文件/子进程、真实 loopback TLS 和 curl CONNECT、DSH Cordis/工具注册组合；部分 Session、LLM 与浏览器错误条件是显式 fixture。没有把它们计作付费模型完成率。

UI 验收加载本地 DSH 源码控件和主题，启动新浏览器进程及临时 profile，通过真实 HTTP 路由验证管理动作、日志下载、六个主导航下的九个功能界面；本轮扩充覆盖 1080 / 520 / 360px 和浅暗主题共 54 组布局，详见[社区 UI 扩充与保留失败](ui-community-expansion-2026-11-01.md)。队列输入是明确标记的 review fixture，未冒充真实执行器模型完成。独立浏览器验收另用已验证可选内核、实际 DSH 工具调用及隔离查看上下文，检查表单、拖动、输入、画面流、授权与取消。不是完整宿主应用全流程测试，也未测试公网站点反检测通过率。

可选内核安装目录可与私有环境数据目录分开；启动、预检和状态读取同一组件目录，档案与登录态留在隔离 home。续跑原生验收还复现了部分随机种子覆盖 DPR 的问题：固定内核的 `0159-display-a-forced-scale-factor-sets-the-pixel-ratio.patch` 明确支持 `--force-device-scale-factor`，现按已校验的档案值显式传入，并用两个随机身份实测 DPR 1 / 2，不通过修改探针期望值掩盖不一致。

benchmark 的驱动必须受信任。文件 SHA256 和身份一致性不能独立证明真的访问了模型；需要结合原生请求记录公开。oracle 只在可信 driver 结束后放入独立裁判副本；目录分离不是阻止恶意 driver 访问主机的 OS 沙箱。超时/异常不得视为“基线正常失败”。`hiddenTestPassRate` 是所有提交的测试成绩；`eligibleHiddenTestPassRate` 只统计具备合格驱动证据的运行。

## 配置与记忆恢复

- 详细入口为 Patchwork → 证据 → 记忆，支持搜索、版本修订、召回控制、来源历史、导出和批量遗忘；操作与隔离边界见[记忆详细管理](memory-management-2026-11-01.md)。
- 设置保存于当前 DSH_HOME 的 Patchwork 配置；重载后读取，不修改主 profile。它是部署级 Patchwork 覆盖，不是会话独立配置；非 Patchwork Agent 不受机制配置影响。
- 记忆只显式召回，最多 5 条，确认后的策略可进一步减小。项目共享需显式 includeProject，仍不能给其他 Agent 授权；会话私有默认不共享。
- 配额满时丢弃不需要的 proposed 或遗忘记录，再重试；不会自动淘汰别的 namespace。
- 出现 MEMORY_DATABASE_INVALID/READ_DENIED 时停止写入，保留 memory.json 原文件。停用所有使用同一 DSH_HOME 的写进程，另存损坏文件，核对 memory.json.bak 的 JSON schema/revision/确认记录，再用临时文件原子替换恢复。修复权限后刷新/重启，并核对记录和 revision。备份是上次有效版本，可能少最后一次更新；不允许从当前会话直接回退全库以影响其他会话。不要清空数据库或按年龄删除仍活跃的 owner lease。

## 可复跑入口（PowerShell）

```powershell
npm test
npm run check:docs
npm run test:benchmark
npm run verify:improvement-real
# 显式渲染验收：浏览器使用新的临时进程/profile；不接管宿主。
npm run test:acceptance:ui -- --dsh-source C:/path/to/deepseek-harness --output C:/temp/ui.json --screenshot-dir C:/temp/ui-screens
npm run test:acceptance:browser -- --component-root C:/isolated-home/patchwork/browser --dsh-source C:/path/to/deepseek-harness --output C:/temp/browser.json --screenshot-dir C:/temp/browser-screens
npm run test:acceptance:native -- --home C:/new-isolated-home --component-root C:/isolated-home/patchwork/browser --output C:/temp/native.json
# 把两份本次验收报告与源码指纹一起收口；报告不能拿旧版本冒充本轮。
npm run verify:closure -- --ui-report C:/temp/ui.json --browser-report C:/temp/browser.json --require-acceptance
```

真实验收入口依赖显式安装的可选包开发依赖和内核；默认 `npm test` 不会下载内核或读取模型凭据。执行证据见[本轮机器报告](checks/closure-2026-11-01.json)。截图保留在验收命令指定目录，不打进发行包。
