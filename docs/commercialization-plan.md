# 商业化与用户方案（草案）

> 状态：**草案**。两处决策待定：商业化路线（§6）与优先目标用户（§3.1）。
> 路线确定前只执行阶段 0–2；阶段 3 不投入实现资源。

## 1. 问题诊断

用 Patchwork 自己的工程标准衡量它自己，当前在用户视角与商业化上的缺口：

| # | 缺口 | 事实依据 |
|---|------|---------|
| 1 | 用户没有定义 | [positioning.md](positioning.md) 只声明“先实现写代码 Agent 的基础”，没有用户画像、场景与竞品 |
| 2 | 价值主张无证据 | README 承诺“减少重复提示和无效 token”，仓库内没有任何度量支撑；Hook 警告是否被 Agent 采纳未测量 |
| 3 | 采用摩擦高 | 安装需要 4 步手工命令（`npm pack` → `dsh plugin add` → `gen-preset` → 手动 `Copy-Item`） |
| 4 | 介绍语描述自我而非用户利益 | “Maintainable coding agent for DeepSeek Harness”说明“我是什么”，未说明“你得到什么” |
| 5 | 无反馈回路 | 没有 issue 引导、用户社区或 changelog 沟通 |
| 6 | 分发被宿主锁死 | 价值分发完全绑定 DSH preset 系统，DSH 用户量即市场上限 |

**可移植性是被忽略的资产**：核心价值由纯 Markdown 提示词与 stdin/stdout JSON Hook 构成，
不依赖 DSH，可直接服务其他 AI coding agent 用户。这一资产目前未进入任何决策。

## 3. 阶段 0：用户定义与问题验证（1–2 周，零代码）

### 3.1 用户画像三档（优先级**待定**）

- **P0：DSH 生态内用户** — 获客成本最低，但天花板 = DSH 用户量。
- **P1：所有 AI coding 用户** — 市场大，可移植性资产直接复用，但竞争在主赛道。
- **P2：团队/企业** — 唯一可能有明确付费意愿的档位，但销售周期长、需要案例背书。

### 3.2 替代品盘点

逐个回答“它的用户为什么选它，Patchwork 多给了什么”：裸 standard preset、
手写 system prompt、CLAUDE.md / Cursor rules / Aider CONVENTIONS.md、
SuperClaude、spec-kit。

### 3.3 待补研究清单

1. AI coding 工具 2024–2026 变现与分发案例（Cursor / Cline / Claude Code plugins / spec-kit）。
2. DSH 生态规模与付费先例（决定路线 A/B/C 的关键未知数）。
3. dev-tool 定价锚点。

## 4. 阶段 1：价值证据（约 1 周，小实验）

- 定义三个可测指标：**warning 采纳率**（Hook 报警后 Agent 是否真改）、
  **返工次数差**（同任务，裸 preset vs Patchwork）、**token 消耗差**。
- 做一次对照实验（同一个中型任务跑两遍），把第一组数字写进 README。
- 该实验同时回答：Hook 的警告到底有没有用。若数字否定价值，先改产品，再谈商业化。

## 5. 阶段 2：降低采用摩擦

- 安装从 4 步压到 1–2 步（目标：`dsh plugin add` 一个 tgz 完成安装，`gen-preset` 自动化）。
- 提供“30 秒上手”文档与明确的卸载路径。
- 介绍语重写为用户利益形态，例如：“让 AI 写的代码像老工程师改的：先调查、最小改动、
  真实验证——不用反复口头纠正它”。

## 6. 阶段 3：商业化路线选项（**待定**）

| 路线 | 内容 | 验证门槛 | 风险 |
|------|------|---------|------|
| A. 生态绑定 | 工具永久免费，价值回流为个人影响力（求职/咨询/接单背书） | DSH 生态活跃即可 | 不直接产生现金 |
| B. open-core | 个人版免费 + 付费团队包（团队规范集、私有 Hook 检查、合规报告） | P2 用户付费意愿验证；MIT 协议需重新审视 | DSH 生态规模可能撑不起 |
| C. 内容变现 | 工具免费引流，把“AI 代码工程纪律”方法论做成付费小书/课程 | 有公众号/社区渠道先跑通流量 | 与主业抢时间 |

推荐逻辑：阶段 0–2 全做（对任何路线都不亏）；数字到手后先评估 A，
若 P1 档验证效果好再评估 B。
