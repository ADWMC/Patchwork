# 浏览器资源管理

日期：2026-11-01。状态：本地实现，尚未发布。配置与功能入口位于 Patchwork 侧栏，不新增独立管理站点。

## 判断依据

[此前内存短测](browser-memory-profile-2026-11-01.md)中，独立 Edge 一页私有驻留为 128.8 MiB，八页为 344.6 MiB；八页的进程工作集合计为 1052.2 MiB，但其中共享页会重复计算。多 Agent 各开浏览器会重复固定成本，所以需要管理运行数量和生命周期。

本轮继续保留每 Agent 独立 browser/context，降低空闲成本：按需启动、限制并发、标签上限、显式回收、可选空闲回收，以及 Playwright/指纹生成器/注入器的延迟加载。延迟加载已落实，尚未测出完整 DSH 的增量节省，不给出节省百分比。

## 使用入口

在当前 Patchwork 会话的「浏览器 → 资源管理」中可以：

- 查看自己的运行状态、标签数、最近采样的私有驻留内存和采样时间。
- 查看当前 Node 宿主匿名汇总：运行数/并发限制、软目标、采样覆盖。汇总不含其他会话 ID、网址、目录、PID 或 Cookie，Agent 工具返回值只含自己的资源状态。
- 点击「采样内存」按需测量。重复点击在 15 秒内复用结果；普通状态轮询不启动系统采样进程。
- 点击「回收当前浏览器」关闭该会话内核，保留有界的网址列表；点击「恢复 N 个标签」显式重新打开。未提交表单、页面内存、滚动位置和未启用持久化的登录状态不保存。
- 明确勾选「允许本会话空闲或容量不足时自动回收」。这是本会话临时许可，不会自动改写其他会话或部署默认值。

自动回收默认关闭。默认允许最多两个活动浏览器；第三个启动会明确被拒绝。只有其他会话此前明确允许回收且当前未受保护时，容量不足才优先回收最久未使用者。当前 Agent 没有选择或操控其他会话的 API。

## 配置

「设置 → 浏览器资源」保存到目标 `DSH_HOME/patchwork/config.json`，重新加载插件后读取。保存成功不等于现有会话已热更新。也可在 `patchwork-runtime` 部署行设置同名字段，用户层覆盖部署值。

| 字段 | 默认值 | 范围与作用 |
| --- | ---: | --- |
| `browserEnabled` | `true` | 是否注册内置浏览器工具；关闭时侧栏停止浏览器 API 轮询 |
| `browserMaxInstances` | `2` | 1–8；当前 Node 宿主的活动/启动中浏览器总数 |
| `browserMaxTabs` | `8` | 1–8；每会话标签总数，包含休眠标签 |
| `browserIdleTimeoutMs` | `300000` | 30000–3600000；允许回收的会话的空闲时间 |
| `browserMemoryTargetMiB` | `512` | 128–16384；近期已测私有驻留合计的软目标 |
| `browserAutoReclaim` | `false` | 新会话是否默认允许空闲/容量回收 |

内存紧张的机器可以把并发调为 1、标签调为 4；自动回收单独决定。不同插件作用域在同一 Node 宿主内的并发/软目标采用已注册策略的最严格值，防止较宽配置绕过较窄配置。多个独立 DSH 进程不共享这个协调器，不构成整台电脑的 RAM 管理系统。

## 生命周期与保护

- 浏览器真正启动前预留槽位，启动失败、关闭和断连释放。最终检查与预留之间不等待，避免同时启动越限。
- 同会话切换不同内核前要求先关闭当前浏览器；不同时保留两套内核。同内核切换环境仍沿用既有验证后替换上下文的流程。
- 每 10 秒检查空闲会话，不为扫描启动额外系统采样。计时器允许宿主自然退出。
- 用户接管、执行/排队动作、录像、传输、仍有效的下载授权、实时画面订阅，以及最近 15 秒的 JPEG 查看都阻止自动回收。过期下载授权不永久保活。
- 回收在会话动作队列内二次检查保护条件；用户在等待期间接管会撤销此次回收。
- 只有实际动作刷新活动时间；状态轮询不刷新。回收后的恢复仍受并发上限和原有文件/URL 权限约束。
- 关闭失败且内核仍连接时保留槽位，不把活动进程伪报成已释放。加密存储保存失败但内核已关闭时，仍保留可恢复网址并报告错误。
- 切走 preset、释放 Agent 或使用旧客户端引用时沿用原有撤权检查；普通会话不注册浏览器工具。

## 内存口径

当前支持 Windows Chromium：通过当前浏览器专用 CDP 的 `SystemInfo.getProcessInfo` 取得 PID，再查询 Windows CIM。只使用校验过的正整数 PID，不读取命令行、不遍历用户 Edge 窗口，也不把原始 PID/系统错误详情返回给模型。PowerShell 隐藏运行，执行超时 8 秒，输出有界，不继承模型 API 密钥。

私有驻留、进程工作集合计和私有提交分别返回；界面重点显示私有驻留。CDP 未列出的辅助进程、DSH Node、侧栏、录像编码器不在这项采样内。它与此前按 Node 进程后代统计的全进程短测口径不同，不做直接降幅比较。

采样结果缓存 15 秒；匿名汇总只使用 30 秒内的已测值。覆盖不足显示未知，不把未采样部分当成零。只有已测压力达到软目标时才拒绝新启动或回收明确允许的对象，运行中的页面仍可能继续增长。这是调度提示，**不是操作系统内存硬上限**。

其他平台、Camoufox、系统计数器失败或采样期间进程变化时显示不支持/未知。不会回退成虚构的零内存，也不会结束不相关进程。

## 验证与范围

具体结果和源码哈希见机器可读记录。验证分为：

1. 全仓自动测试及资源协调器负测：并发预留、失败释放、保护条件、采样缓存、撤权、异常关闭和恢复。
2. 真实 Cordis/DSH 服务组合：配置进入 runtime、普通会话无工具、旧引用撤权、关闭浏览器能力后其他 Patchwork 工具仍在。
3. 真实隔离 Edge：四页采样、容量拒绝、接管保护、手动回收/恢复、空闲回收、容量回收与 preset 撤权。
4. 实际 React 组件和鉴权浏览器后端：按钮、采样、恢复、禁用后停止轮询，320/380/1280 px 浅深色无横向溢出。

Browser plugin 不可用，本轮使用独立 Playwright。组件 harness 使用测试主题 token；不冒充完整 DSH 侧栏端到端验收。没有发送模型请求，没有修改主 DSH 或用户浏览器。长期泄漏、非 Windows 真实内核、跨进程统一预算与崩溃后跨重启恢复尚未验证或实现。

分发和后续 portable runtime 方案见[分发设计](browser-distribution-2026-11-01.md)。
