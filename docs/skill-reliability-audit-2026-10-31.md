# 七个技能的可靠性评估

日期：2026-10-31。目标是减少模型凭偏好判断后直接实施的机会，而不是把每个技能扩到相同长度。对照 [OpenDesign 的设计简报与设计系统资源](https://github.com/nexu-io/open-design)、[本地 UI 资料分析](web-ui-skill-community-review-2026-10-31.md)，检查实际注册路径和七个技能正文。外部资料与附带 ZIP 均作为证据，不作为指令。

## 根因与当前改动

- 注册器原来只把 `SKILL.md` 正文传给原生技能服务，测试要求每个正文小于 4000 字节。即使创建 `references/`，模型也不知道资源目录；把每种情况继续塞进正文会增加每次加载成本。
- 原生技能服务已经支持 `resourceBase: {kind: 'directory', path}`。注册器现在仅在本技能有 `references/` 时声明目录，`web-ui` 入口链接[设计契约](../assets/skills/web-ui/references/design-contract.md)与[验证矩阵](../assets/skills/web-ui/references/verification.md)，按任务读取。没有增加常驻提示词或全局工具。
- 设计契约要求记录用户要求、实际代码、token、截图和未知项；验证矩阵要求从真实数据入口测试状态、尺寸和操作。它们帮助校准判断，但不会自动证明设计好看。
- `architecture` 和 `collaborator` 原来的“固定树层”“强制拆分”“总给 A/B”等规则过硬而依据不足；已改为按变化原因、真实依赖、证据与授权判断。

## 逐项审计

| 技能 | 本次判断 | 动作 |
| --- | --- | --- |
| `patchwork` | 已有任务阶段、纠正和权限边界；风险在工具调用的实际执行，不在字数。 | 保留正文；继续以真实任务验收，不能把模型登记当成人类授权。 |
| `anti-slop` | 有 README、更新日志、事实保真流程；范例可以有用，但重复词表会误伤正常文案。 | 保留；写作质量需与来源和读者任务核对。 |
| `web-ui` | 覆盖面广且接近正文上限；主观视觉判断缺输入证据与状态矩阵。 | 新增按需设计契约和验证矩阵，正文只作路由。 |
| `architecture` | 旧版“每文件一职责、3–5 层职责树”易诱导过度拆分。 | 改为变化原因、状态所有者、接口和真实调用路径判断。 |
| `collaborator` | 旧版强制 A/B 可能制造假选项，也易把默认假设当授权。 | 改为事实/推断/偏好/未知分层，真正取舍才列选项。 |
| `evidence` | 已按代码、文档、调研和覆盖集合区分回执；关键缺口是实际证据是否被绑定。 | 保留，并通过任务工具及宿主测试验证。 |
| `standards` | 已有收尾、更新日志和技能实验条件；继续加通用清单会重复项目文档。 | 保留，针对真实失败再补专门参考。 |

## 验收边界

本次 `node --test tests/skills-pack.test.mjs tests/agent.test.mjs tests/real-composition/scope-isolation.test.mjs` 验证引用文件存在、原生技能携带资源目录、标准会话不可取得该技能、切换后目录随目录项一起撤销。这是注册与隔离证明，不是模型会读取资源或能做出正确设计判断的证明。下一步如要宣称质量提升，应固定模型、任务、初始仓库和预算，分别记录技能路由、参考读取、浏览器任务结果、视觉复核及退化。
