## 1. 建议与目标

建议按“记住项目事实 → 从失败产生候选 → 在隔离 DSH 中验证 → 按项目启用、随时回退”建设。UI/UX、表达保真和代码维护性进入同一条任务与验收流程，不新增一个常驻的万能提示词。

三个直接面向使用者的结果：

1. 新会话知道项目的宿主入口、设计约束、已确认决定和被纠正的事项，并能解释来源；旧信息可以纠正、失效、删除。
2. Agent 遇到重复失败会提出具体改进；启用实验后，可以在固定预算内自动验证候选。只有证据达标且经审阅的版本才影响后续任务。
3. 做界面先读宿主和用户路径，改文字先保住事实与作者声音，改代码验证真实行为；完成声明能追到产物和回执。

本期不训练模型权重、不跨所有项目自动推广、不后台无限运行、不自动改评价器或发布插件。这里的自进化对象是**任务方法、检索策略和按需技能经验**。

## 2. 当前能力与必须补齐的缺口

## 3. 架构与选型

```text
当前用户输入 + 当前仓库事实
              ↓
现有 task 契约 / revision / 回执
       ├─ 来源引用 → 记忆候选 → 确认或重新核验 → 有效项目记忆
       └─ 失败回执 → 单一改进候选 → 独立 DSH 对照 → 审阅 → 项目经验版本
                                      ↑
                 固定任务集 / 外部裁判 / 预算 / 回退点

有效记忆 + 已启用经验 → 有范围的检索 → 当前 Patchwork 请求视图
全部管理 → DSH 现有侧栏；元数据诊断 → 现有日志系统
```

| 决策 | 本期采用 | 暂缓或排除 |
|---|---|---|
| 持久化 | 原生 Session 保留任务与原始回执；本地 SQLite 保存跨会话索引、事实版本、候选与关系 | 不复制完整聊天和工具输出；不先引入外部记忆服务、图数据库或 Python 常驻进程 |
| 检索 | 结构化过滤 + 词法检索；中文短词有专门路径；先做可解释基线 | 向量/混合检索仅在实际漏召回案例证明必要后接入，并单独评价隐私、成本与删除 |
| 学习 | 借鉴 LangMem 的范围接口、Hindsight 的来源/派生分离、GEPA 的逐例反馈 | 不直接嵌入它们的整套运行时；不照搬 ECC 的缺项目时全局回退 |
| 自动程度 | 自动记录最小事件、归并失败、产生候选；显式启用实验后自动跑有界对照 | 不凭自评分或重复次数自动变成全局规则；不自动改源码、安装包、模型或权限 |
| 质量方法 | 宿主一致性、用户路径、事实与行为保真；沿现有短技能按需加载 | 不以禁词表、AI 检测器或“更像人”分数代替验收；不导入远程 SKILL 后直接执行 |

### 3.1 存储兼容性先于实现

推荐 SQLite，但**不能在当前 `node >=22` 声明下无条件 import `node:sqlite`**。Node 官方 v22.13.0 文档将其列为开发中的 API；同步数据库操作也不应阻塞模型主循环。

- P0 为实际 DSH 打包运行时做能力探针；选择并锁定支持的 Node/数据库适配器版本，补齐 Windows/Linux 打包与 worker 测试，必要时明确提高最低版本。
- SQLite 读写集中到 worker：事务、版本迁移、唯一约束、CAS revision；不同进程的并发不能只依赖现有进程内 Promise 队列。
- 启用 foreign keys；并发、锁等待与 WAL 的使用以目标文件系统测试为准。不把网络共享盘或任意同步目录当作已支持数据库位置。
- FTS 仅为派生索引，事实表是权威。trigram 对一两个字的查询不能直接套 MATCH；使用有范围、有上限的结构化键/短词匹配。测试中英混排、标点与否定。
- 适配器不可用、数据库损坏、迁移失败分别返回明确状态；不静默退回临时内存并显示“已记住”。核心任务流程可继续，记忆和学习停用。

当前实现先采用可移植的本地权威 JSON 文件适配器，显式标记 `file` 持久化；SQLite/worker 仍是后续兼容矩阵通过后的替换目标，不把 Node `node:sqlite` 在 DSH 打包环境中的可用性当成既定事实。

## 4. 记忆模型与生命周期

### 4.1 四层信息分开

| 层 | 存什么 | 如何生效 |
|---|---|---|
| 本次任务 | 当前目标、授权范围、阶段、要求、纠正和验收 | 复用 `src/task/`；当前任务 revision 优先；不能靠历史记忆跳过契约 |
| 项目事实与约束 | 真实入口、测试命令、宿主 token、已确认决定、项目内偏好 | 确认或新鲜证据核验后，在当前项目读取；文件改变则失效或重验 |
| 候选经验 | 哪次失败、建议改变、适用触发、反例、待验证假设 | 可以审阅和实验；不作为已验证规则进入普通任务 |
| 已验证程序经验 | 通过对照的原子方法、适用范围、排除条件、版本和回退点 | 明确启用后按触发使用；不把所有经验拼进每次 prompt |

诊断事件只保留已有日志白名单元数据。原始材料继续引用宿主事件或产物；不要因“有助学习”永久保存整段提示词、源码、凭据和工具原文。

层次决定信息用途，**可见性另外决定谁能读**，不能因为某条信息与项目有关，就默认公开整个来源会话：

| 可见性 | 默认内容 | 其他会话怎样使用 |
|---|---|---|
| session-private | 当前目标、临时要求、草稿、未确认推断、任务进度和候选 | 仅原 session；重启可恢复但不因此转成共享，fork 不获得私有记忆的读取权 |
| project-shared | 经确认的项目约束；项目策略明确允许、且已核验的结构化仓库事实 | 同 instance/profile/project、实际选择 Patchwork 且开启项目读取的会话可按需检索 |
| explicit-linked | 将来显式关联的项目间精选条目 | V1 不启用；关联不能把全部会话、私有来源或执行权限一起带过去 |

从聊天自动提取的内容默认 session-private；成为项目共享记录需要明确确认，或命中已开启的结构化事实白名单政策。共享的是原子事实，不是整段对话、当前任务的行动授权、通过状态或私有来源正文。

### 4.2 最小记录契约

`MemoryRecord` 至少包含：`id / schemaVersion / namespace / visibility / ownerSessionId / kind / key / value / conditions / status / validity / revision / sources / observedAt / ingestedAt / validFrom / validUntil / verifiedAt / expiresAt / supersedes / derivedFrom / sensitivity`。

- `sources` 引用 session、事件/回执 id，或文件路径、内容 hash 和读取版本；明确 `repo-observed / ui-confirmed / model-proposed / imported`。来源缺失就是 unsupported，不是自动可信。
- 自动核验只覆盖白名单结构化事实，例如实际 package scripts、公开入口和已读取 token 定义；自由文本中的指令、模型推断和“测试已通过”不能凭引用文件而转正。文档支持、事实可信与真实行为通过分别记录。
- `status` 为 proposed / active / superseded / revoked；`validity` 单列 fresh / stale / conflicted / expired / unsupported。确认过不等于永远新鲜。
- `observedAt` 是来源事件或文件快照的观察时间，`ingestedAt` 是接收时间；`validFrom/validUntil` 表示事实适用区间，未知留空。晚导入的旧材料不因此比当前文件更新；相对日期依据来源时间/时区解析，保留依据，不能编造精度。
- 记录条件和否定范围，例如“该插件 UI 使用 DSH tokens”，不能抽成“所有项目禁止自定义样式”。一次“这轮先调研”属于本任务，不升级为永远禁止实施。
- 模型 confidence、出现次数和检索点击只用于排序参考，不能代替来源、正确性或用户确认。

### 4.3 写入、纠正、冲突与删除

1. **捕获：**现有回执触发最小失败事件；新发现的事实只生成候选。模型提取是可关闭的有界调用，默认不额外消耗模型费用。
2. **转正：**用户经受控管理入口确认，或服务端重新读取并核验低风险仓库事实。模型自述、外部文档内的“记住”指令、恢复记录中的 user 标签都不能自证授权。
3. **纠正：**当前指令立即改变当前 task；冲突记忆暂停使用。确认新版本后 supersede 旧版，连带失效派生摘要、相关经验、缓存和进行中的实验。默认检索不读旧版；显式 asOf 历史查询可在原权限内读取保留版本，用于解释当时情况，不能指导当前执行。revoked、已忘记正文或来源权限失效的版本不因历史查询开放。
4. **冲突：**同一 key 在重叠条件下矛盾，标记 conflicted，展示原话/来源/时间；无法确定时不悄悄用最后一次写入覆盖真相。仓库事实和人的偏好分别处理。
5. **删除：**先撤销检索和激活指针、递增 namespace epoch，再事务删除正文及派生索引/缓存，取消相关排队写入。保留不含正文的 tombstone/id 与来源抑制标记，防止旧 checkpoint、导入或异步结果把它复活；提供按 key/条件“不再记住”的抑制选项，不能仅换一个 id 就重新提取；显式恢复需新确认。
6. **物理保留：**版本历史不是无限保留正文的理由。提供忘记正文与删除关联记录的策略；WAL、备份与已导出 ZIP 有独立清理流程，不能承诺 SSD 安全擦除或已交给第三方的副本可收回。

过期策略按类型配置，不能用统一 TTL 证明正确：仓库事实依赖 hash，偏好依赖确认，候选可到期清理，已启用经验依赖版本和回归。旧 Session checkpoint 永不批量导入为 active 事实或通过证据。

### 4.4 写入状态与读己之写

操作状态单列 queued / committed / indexed / failed / cancelled，不与事实的 proposed/active 混用。queued 仅表示接受并排队；committed 表示权威记录与 revision 已事务提交；indexed 表示指定派生索引覆盖该 revision。回执包含 operationId、recordId、revision、状态与可见性，UI 不把排队显示成“已记住”。

用户明确添加/纠正的结构化事实走直接事务，并核验确认与共享资格；聊天提取仍先成为候选。当前任务的明确纠正直接作用于 task，不等异步提取。结构化/词法层尽可能同事务，未来异步向量索引用水位标明落后；不能以向量未更新为理由无限阻塞前台。

持有写入回执的会话可按 id/revision 在权威层读取已提交且有权查看的记录；索引未追上时返回 pending/index-lag，或在授权范围内有界回查权威层。无命中、待提取、索引落后、服务不可用分别记录；权限失败拒绝读取，可选检索故障让原任务继续，但不能伪装成已查全库。用户可见状态不得暴露其他会话私有记录是否存在。

后台队列有容量、超时与有限重试，任务开始及提交都复核 scope generation、epoch、revision；切换/删除后的迟到结果丢弃。队列优先保存受控来源引用，不复制整段敏感历史。删除验收必须覆盖索引重建、恢复与旧任务回流，不能只检查即时 search 为空。

## 5. 隔离与请求上下文

### 5.1 服务端范围

命名空间使用 `instanceId / profileId / projectId / presetId`，会话临时状态再加 sessionId。索引查询先做范围与有效性过滤，再排序；缓存键至少包含 namespace、epoch、任务 revision 和检索策略版本。

- instance 与 canonical home 绑定；profile 读取宿主 `ctx.get('profileContext')` 的 home/dir 等服务端事实，不能只用同名 profile。该契约来自 app-boot，不假定所有嵌入式启动都有；缺失时须显式绑定受信部署范围，否则禁用持久记忆。
- project 从宿主已解析的真实工作根建立注册记录，解析 symlink/junction。不同 worktree、clone 默认分开；同一个 Git remote、目录 basename 或请求 header 不代表同一个项目。
- 同项目并不意味着同一个任务：必须同时校验记录 visibility、ownerSessionId 与接收会话的读取模式。session-private 不参加其他会话的召回，不能先召回再指望模型自行忽略。
- 项目关联由用户明确建立；V1 不开放 user-global 共享。将来共享也只共享已确认条目，绝不把项目事实凭重复次数推广到全局。
- 路径规范化用于分区，不授予文件权限；本机命名空间也不是多用户 ACL 或 OS 沙箱。

### 5.2 每个边界重新核对

复用真实 `isPatchworkAgent` / `resolvePatchworkAgent`，覆盖：工具注册和调用、记忆读写、异步提取开始/返回、模型派发、实验排队/启动/结算、Web 查询/提交、导入/导出、缓存交付和版本启用。提交同时核对 scope generation、namespace epoch 与 expected revision。

切走 Agent、任务取消或项目改变时，停止检索和调度、取消可取消请求、清空前端草稿及会话缓存；已发出的模型请求不能假装撤回，迟到结果不注入、不激活、不计作当前证据。清理实验子进程属于释放资源，可以完成，但不能借清理继续学习。

这里的清理绑定具体 session/operation，不能因 A 切换 Agent 就清掉 B 的缓存、停止 B 的实验或修改 B 的 task。项目共享记录撤销时，相关缓存失效是必要的数据一致性动作，但不向其他会话插入消息或覆盖它们的当前目标。

### 5.3 不能把永久历史当临时记忆通道

**选定方案：请求视图适配器 + 能力门槛。**P0 验证宿主公开扩展点能否形成按当前 composition 过滤的模型请求视图，并覆盖普通调用、prepared route、重试、工具回执、压缩和恢复。不得直接修改冻结 request 或私有 Session 内部。

- 记忆正文和经验投影只进入当前 Patchwork 的请求视图；原生日志持久化 id/revision/检索原因等最小元数据，不能先把正文 append 到永久 user/message 再期望切换时忘掉。
- `patchwork_memory` 的模型返回值同样属于该通道；不能仅解决自动注入，却把检索正文通过普通永久 tool-result 泄回历史。需要标记来源并由宿主投影契约处理。
- 若当前公开 API 无法做到，先交付数据管理与候选收集，**自动读取/注入保持禁用**；形成独立上游扩展提案，待真实请求级负测通过再开放。不得降级到全局 `llm/stream` 篡改或修改主 DSH 文件。
- 已经展示给用户、写进产物、被助手转述进正常对话的信息，无法凭撤销记忆令模型“失忆”。严格敏感材料不入库、不投影；需要内容完全隔离时使用独立会话。此边界必须在 UI 与文档说明。

### 5.4 检索如何真正使用

进入已验证的请求通道后：读取当前任务类型和引用 → 过滤范围/可见性/撤销/冲突/过期 → 匹配 key、触发与排除条件 → 返回少量正文和来源 → 记录实际采用情况。当前指令与当前仓库证据优先于旧记忆；记忆永不授予执行、付费、跨目录或发布权限。

检索正文、证据和导入内容始终作为有来源的数据传递；采用有界结构化字段与来源标记，不提升为 system/developer 指令。测试持久化提示注入：材料里要求改规则、调用其他项目工具或泄露提示词，不能变成已启用经验。提示标记本身不是安全保障，仍须结合范围和工具权限校验。

读取分三级，避免把数据库当作常驻 prompt：

1. **库内筛选：**服务端根据真实范围、当前任务类型、实体/文件和记录条件查询。候选池条数、时间与计算有独立上限；最终最多投影 5 条不等于只检索 5 条。候选索引与全文留在库里；不先把全部目录交给模型选，也不为每一轮额外调用模型总结一次。
2. **短投影：**最多选 5 条，带短事实、适用条件、id/revision 与必要来源。无相关项就不注入，不能为“利用记忆”硬找相似规则。每次请求内按 id/revision 去重，并与已有任务上下文中的相同事实去重。
3. **按需详情：**确有需要才通过 get(id, section/cursor) 读取指定片段。详情替换当前视图里较不相关的内容，和自动投影共用预算，不能每次工具调用又加一份满额正文。来源会话的正文读取另作权限检查，共享一个事实不等于允许读取原会话。

分别记录 retrieved（检索候选）、admitted（预算与有效性允许）、sent（实际派发请求中存在）；被预算裁掉或派发前失效的条目不标记 sent，后续仍可检索。去重绑定具体请求/id/revision，不能将某轮候选永久视为模型已读。sent 不等于理解或采用；经验反馈以可关联的行为和验收为准，无法归因就记 unknown。

当前请求使用冻结的记忆版本集合，其他会话的新写入不会在流式生成中途改变它。下次请求只重新核验当前相关条目；受影响的记忆写入或经验启用需 CAS 校验，不能混用两个版本。存在冲突时保留当前用户要求，相关旧记忆标记暂不适用，而不是强迫用户服从记忆。

### 5.5 其他会话需要记忆时怎样用

记忆由项目启用后，每个 Patchwork 会话可选择 off / session / project；项目政策可给新会话一个默认读取模式，用户可单独覆盖。部署禁用仍优先。

| 接收会话 | 可读集合 | 默认不会获得 |
|---|---|---|
| 同项目 Patchwork，project 模式 | 本会话私有记录 + 有效项目共享事实/已启用经验 | 别的会话的临时指令、草稿、候选正文、进度和 ready |
| 同项目 Patchwork，session 模式 | 本会话私有记录 | 项目共享记忆的自动注入；其他会话私有内容 |
| 任意会话，off 模式 | 不读取、不捕获新的插件记忆 | 记忆正文、记忆工具和自动提取 |
| 不同项目或不同 profile 的 Patchwork | 自己绑定范围内的记录 | 同名目录或相同 remote 所对应的另一个范围 |
| standard 或其他 Agent | 不接入 Patchwork 记忆 | Patchwork 的工具、技能、检索、实验或通知 |

这使同一项目的新 Patchwork 会话能复用稳定知识，又不继承另一个任务的“现在应该干什么”。用户若以后要让其他 Agent 使用，需新增独立、显式启用的消费适配与能力合同，不能因本次讨论便扩大到所有 Agent。

UI 在记录上标明“本会话 / 本项目”，提供“用于本项目”；在当前会话提供读取模式和“本次不采用此条”。不向所有会话广播记忆消息，不自动修改别的会话的开关或系统提示。暂停读取不删除数据库，其他获准会话仍可使用。

### 5.6 上下文预算与累积控制

建议短投影的绝对上限为 800 tokens、最多 5 条，但**800 是上限，不是每轮必须添加的额度**。实际预算随当前模型窗口和剩余空间缩小。拟议计算：

```text
C = 当前实际路由模型可用的上下文窗口
T = 尚未装载记忆时的完整请求输入计量（含系统、任务、工具定义、历史等）
R = 本次请求预留的最大输出
S = 序列化、计量误差等安全余量
M = max(0, min(800, floor(C * 0.02), C - T - R - S))
```

800 和 2% 是待真实任务校准的初始策略，未有证据证明其普遍最优；S 按模型/适配器明确配置和验证，不写一个通用常数假装精确。多跳任务另外记录必要证据覆盖和裁剪损失，在离线对照后修订政策；运行中不为补齐材料悄悄放大限额，证据不足明确说明缺口。

- **统一计量：**记忆摘要、必要来源、索引说明、经验正文、分页 get 结果与重复副本统一核算；协议开销一并计入总请求。cache 命中可能改变费用，不能当作不占上下文。
- **动态让位：**接近窗口上限时先减条数、减片段，不够就 M=0，不装载记忆；不能为塞记忆而删当前用户要求、验收证据或擅自启动额外压缩。基础请求本来就过大时，仍须由既有上下文策略处理，记忆模块不能承诺解决所有溢出。
- **替换而非追加：**每次请求只有一份受预算约束的记忆视图。下一步按新任务状态重新选择/替换，不把上一轮 800 再加下一轮 800。长期库增长不应使模型输入线性增长。
- **工具也受限：**每次 get 前预留返回及协议开销，正文不能超过本请求剩余额度；超出时返回受限状态/分页提示并计量，不返回未截断全文。不能让工具历史绕过短投影限制。
- **计量能力：**C 和 tokenizer 必须绑定实际 provider/model，重路由后重算。没有可靠窗口或 tokenizer 时不能声称硬 token 上限；只显示保守估算，且不开放临界空间下的自动装载。
- **派发前复核：**记忆组装后再计量最终请求；超限则移除记忆或拒绝该次装载，不能带着超限请求继续发送。该检查必须与公开请求投影/工具历史合同一起实现，不能只在数据库 search 阶段截一次文本。
- **检索次数：**默认每个新输入/相关任务变化最多一次自动检索；工具显式检索有次数与输出上限。缓存结果使用前仍核验范围、记录 revision 和 epoch。空命中不持续追加通知。
- **可观察：**UI 显示实际/估算的本次记忆占用、有效上限、选中条目及未采用原因；完整窗口不可得时明确 unknown。诊断只记数值、id 与拒绝码，不复制正文。

例如同项目 A 做 UI、B 改后端：A 可能读宿主 token 约束，B 可能读真实测试命令；两者按各自任务独立选取。同一个事实被两者使用不意味着共享整份对话，也不意味着向两边注入同一套经验。

与 SoL 机制协作：OCC 只恢复当前有效 id/revision 的短投影，不从压缩摘要重新学习；EPR/OP 保留原始证据引用而非把裁剪结果当唯一事实；AF 不绕过检索与写入前的 revision 校验。量化检索及新调用对 token/cache/延迟的净影响，不预设一定节省。

## 6. 自进化闭环

### 6.1 可自动做什么

默认 `collect`：自动记录最小失败元数据、去重并形成候选；从已有事件中整理假设。可选 `trial`：用户配置范围、预算、模型和隔离环境后，在这些边界内自动生成单一候选、运行对照、收集逐例反馈并提出结论；无需每一步重复询问。没有配置实验预算就停在候选，不偷偷使用主会话凭据或启动后台定时任务。

候选只能改变一个可描述的对象：某一触发方法、某条检索策略参数、或某个有条件的短技能经验。每个候选保存带类型的 sourceCases（失败候选另关联 failureIds）、假设、最小 diff、适用/排除范围、parentVersion、数据集 hash、预算、回退版本和风险类别。

主要从真实失败和明确纠正学习；也可从可测的重复开销、已验证的成功方法提出 optimization 候选。成功轨迹不自动成为规则。v2 来源需区分 failure/correction/inefficiency/verified-success，关联真实 sourceCases；当前 v1 只接受 sourceFailureIds，不能为兼容它而伪造失败记录。

| 变更 | 处理方式 |
|---|---|
| 补全新鲜项目事实、撤销过期记录 | 按记忆生命周期自动核验；不算程序经验升级 |
| 项目内方法/检索/技能经验 | 可自动产生和实验；通过后在 UI 审阅、按项目启用版本 |
| 工具执行代码、安全边界、存储 schema、全局策略 | 回到普通开发审查、完整回归与发布流程；不能由学习器运行时替换 |

接纳与激活是两步：accepted 表示评测档案通过审阅；active 是某个项目启用该版本。用户可禁用整条经验或回退指针；升级失败不会令插件无法启动。V1 不自动激活未审阅经验，自动化价值在发现与验证，而不是绕过审查。

### 6.2 独立 DSH 实验，不碰主环境

实验器使用独立 home、profile、工作目录、端口、Session、数据库和日志，只启动自己创建并登记 PID 的子进程；启动失败直接报错，不能回连主 DSH。

- 基线快照包含用户认可的当前工作树状态，包括有意的未提交修改；先生成允许路径 manifest，排除凭据、`.env`、真实 home、无关 untracked 及越界链接。不使用 `git reset/clean/checkout` 清理当前仓库。
- baseline/candidate 的初始快照、依赖锁、宿主、模型路由、工具权限、任务输入、采样参数和预算一致；分别独立工作副本，防止一次试验的缓存、记忆和修改污染另一次。
- 实验不自动继承长期记忆。三组对照使用显式冻结输入；学习器不能查看留出答案、裁判源码或修改评测策略。修复任务可读任务测试，但隐藏验收由外部裁判执行。
- runner 持有控制目录与只写回执通道，核对控制文件/裁判 hash、进程退出、实际产物和 Session 调用。普通 shell 同 OS 用户不是安全沙箱；不能强制隔离时标记 trusted-local-only，不运行不可信外部候选，也不把该设置宣称为防恶意篡改。
- 授权模型路由只传给实验进程；不复制整份用户配置、在命令行回显 key 或写入仓库。记录 provider/model/是否可用即可。
- 用户切走 Patchwork 或预算耗尽后停止派发，回收自己创建的资源。晚到回执标记 cancelled/incomplete，不接入当前项目激活指针。

不直接执行 pi-autoresearch 的主目录提交/清理循环；借鉴其检查与 keep/discard 记录，在自己的隔离 runner 内实现有界流程。

### 6.3 评价器升级

保留当前结构检查作为 v1 档案 lint；新增 v2 独立校验，不把旧手填 JSON 自动认证为真实实验。

1. **回执真实：**runner runId、宿主/session、工具调用、退出/取消状态、产物 hash、评价器版本与原始证据能相互对应；只写 `mode: real-host` 不足以通过。
2. **逐例结果：**每个 case 分开记录 passed / failed / unknown / not-run；缺证据不填零。允许 repair 类基线在目标案例失败，候选必须修复，已有通过控制组不得退化。optimization 类要求两组都满足硬正确性。
3. **多目标且有顺序：**隔离/安全/事实与行为保真先过硬门槛，再看 UI 可用性、可维护性和成本/延迟。审美提升不能抵消越权、事实丢失或功能失败。
4. **调优与留出：**从任务族划分而不只换 caseId，避免同一题改名泄漏。生成器只读调优反馈；留出由外部裁判运行。若据留出失败继续修改，该集合转为调优，重新留出后才能再次提请接纳。
5. **实质变化：**预先声明目标指标与容忍范围，报告全部失败和 sideEffects；没有增益或收益证据不足就保留基线。采样次数少时标记探索性，不宣称统计显著。
6. **可回退：**激活绑定项目、来源、parentVersion 和可撤回指针；遇到新的严重回归立即停用并登记原因，不能自动放宽门槛“救活”候选。

用量分别记录输入/输出/cache hit/cache write、工具用量、实验总耗时与每例延迟。金钱费用需有版本化计价或供应商账单；未知即 null/unknown，不把缺价格填成 0。未知成本可支持纠错分析，但不得通过“更省钱”接纳条件。

### 6.4 有界预算

可选试验的建议初始上限：1 个候选、12 个 lab Session、60 次模型请求、合计 100k 输入输出 tokens、30 分钟 wall time；这些是需要实测校准的保守配置示例，不是默认启动授权，也不代表一定足够。

预算计入候选生成、反思、两组运行、重试和压缩；派发前预留单次最大用量，返回后结算。任一上限先到即停，未完成显示 incomplete，不能缩掉留出集或自动加预算。没有单次最大用量/可靠计数时不能声称硬 token 上限；金钱上限需额外配置可靠计价。

完整接纳实验所需预算另行预估并配置，不能把 12 个探索 Session 伪称为完整回归。机器重启恢复时保持停止状态；只有重新检查当前范围与授权后才可续跑。

### 6.5 自动闭环与启用后的反馈

记忆负责保存有来源的记录；自进化负责证明一种方法在给定范围内比现行方法更好。两者通过版本和证据关联，不把“保存了经验”当作完成学习。

```text
真实事件 / 用户纠正 / 已测开销
          ↓
归并同类问题 → 一个可反驳的假设 → 一处候选变更
          ↓
冻结基线 + 独立 DSH 任务副本 → 调优对照 → 留出验证
          ↓
失败 / 超预算 / 不确定 → 淘汰或保留候选，沿用现行版本
证据达标 → 待审阅 → 接纳 → 对本项目启用新版本
          ↓
后续任务记录实际采用与验收 → 持续观察 → 保留 / 撤回至上一稳定版本
```

开启 trial 并配置预算后，候选生成、实验派发、结果归档、淘汰和报告可以自动进行；V1 的新版本激活仍经审阅。不能把“自动写一条反思”叫作完整自进化，也不能宣称当前已有这些自动阶段。

启用后只从真实任务取最小反馈：是否命中触发、是否实际采用、通过/失败/未知、版本和相关回执。工具正常返回、模型自评、用户未反对都不等于改进成功。后续观察可发现回归，但普通任务中的相关性不能代替受控对照，也不自动触发新付费实验。

无新证据、无可测变化或到达本轮预算时结束，不继续套一轮“反思 → 反思反思”。相同失败用类型、目标与证据归并；不同版本或不同条件保留差异，不能把一次 UI 失误归成所有项目都适用的规则。

### 6.6 经验如何共享而不改变别的任务

- **来源与候选：**继承源记录的私有性。进入项目实验集前，先确认可使用的任务材料，或按项目政策生成不含私有正文的最小复现；不把私有对话直接送入共享评测集。
- **启用范围：**`activeVersion` 按 instance/profile/project/preset 绑定。项目共享事实不等于共享实验权限；其他会话读取一条经验，不会因此获得启动实验、改工具或发布的授权。
- **消费条件：**接收会话须选择 Patchwork、允许 project 模式，并匹配经验的任务类型与排除条件。session/off 模式不读取项目经验。个别会话可本次不采用，不修改全项目的版本指针。
- **任务版本固定：**普通任务开始时固定所用经验版本；A 启用新版不热替换 B 已在执行的方法。新版供后续新任务选择，当前任务需显式重绑定才能使用，且仍受当前任务要求约束。
- **撤回例外：**严重回归撤销相关版本；依赖该版本的任务在下一派发点停止采用它，并回到已审稳定版或不使用该经验。只影响确实依赖该版本的投影/实验，不关闭整个插件、不取消无关会话。
- **回退范围：**回退改变后续方法的选择，不自动 git reset、删除产物或撤销已经发生的外部操作。已有产物如需修复，进入当前任务的正常纠正与验收流程。

两层版本分别处理：事实记忆按请求核验新鲜度；程序经验默认按任务固定版本。两者被撤销时都不能继续读取旧正文；不得以“固定版本”为由绕过撤销。

### 6.7 不挤主上下文，也不无限占用资源

失败档案、完整轨迹、候选 diff、调优反馈和测试报告都留在数据库/实验目录，普通对话不自动阅读。某条已启用经验命中任务后，仅提供必要的短方法、条件与证据引用，计入第 5.6 节的同一记忆额度；自进化不另领一份 800 tokens。控制参数和版本管理留在服务端，不把整个学习器配置注入模型。

实验使用独立 Session 的上下文和已授权学习预算，不占主任务的消息历史；其所有模型调用仍计入实验总用量。当前会话只在请求时获取简短状态或结果摘要，报告详情按需读并受相应任务预算约束。

独立进程仍共享本机 CPU、磁盘和供应商额度，不能承诺零性能影响。初期实验并发最多 1，限速、可暂停，默认不后台启动；没有可靠的宿主忙闲信号就只运行显式启动的有界批次，不猜测“用户空闲”而抢资源。普通会话不承担学习开关、预算、重试或通知。

### 6.8 一个具体的 UI 经验候选

假设真实任务在改 DSH 侧栏后出现深色不可读，且用户指出“没有融入宿主”。候选可以是“DSH 插件界面修改前，先核对宿主 token 与原生控件”，而不是“所有页面一律改成某种视觉风格”。

候选在相同初始快照、模型和预算下，对照现行流程与这一处方法变化；用真实隔离 DSH 检查浅/深色、窄栏、键盘与原功能，再用未参与调优的另一插件界面验证，并加入纯后端任务不应触发的控制案例。视觉评价与行为检查分开。

通过后形成带 trigger/exclusions/version/evidence/rollback 的短项目经验；未来符合条件的新 Patchwork 任务可用。用户若只要求调研，经验只能引导读宿主资料，不能扩大授权去改 UI。若后来换宿主版本或经验造成回归，则失效重验或撤回；不静默越过原验收。

## 7. 将 UI/UX 与去模板化融入产物流程

这里同时覆盖“Patchwork 自身管理界面”与“Agent 为用户制作的产物”，两者共享证据方法，但不能把 DSH 的样式强套给所有产品。

| 任务 | 先读什么 | 怎样做 | 什么算验收 |
|---|---|---|---|
| DSH 内插件界面 | 当前宿主入口、slots、原生控件、token、主题切换和现有信息结构 | 先走用户路径，复用宿主组件；只按需加载 web-ui 及项目设计事实 | 真宿主浅/深色、窄侧栏、键盘、状态反馈和实际操作；不以截图漂亮代替可用 |
| 其他项目的 UI | 项目自己的设计系统、目标用户、内容与关键路径 | 用真实内容确定布局、层级、密度和动作；不一律套 DSH 或某个流行模板 | 首次任务、出错恢复、空/加载/长内容、响应式、可访问性与行为测试 |
| UX 评审 | 谁在何处为什么用；既有行为与失败记录 | 逐步走真实任务，指出阻碍与修复优先级；不把每个表单变成指标看板 | 用户能否完成任务、出错能否恢复、交互反馈是否可信；主观判断单列 |
| 写作/README/更新日志 | 事实来源、作者声音、读者动作、实际实现状态 | 先保留主张与限定，再删重复空话；仅调研不写成已实现，正常段落允许不改 | 数字/日期/否定/范围/条件/时序/归因逐项不变；命令可用；编辑前后对照与人工评阅 |
| 代码清理/评审 | 调用边界、错误路径、兼容承诺和现有测试 | 小范围修复，保留安全与失败处理；避免无依据抽象、注释翻译和装饰性重构 | 真实行为、失败路径、可维护性；不以行数下降或 lint 通过证明任务完成 |

对“AI 垃圾”的操作化定义是**无信息的装饰、与宿主不一致、虚构或强化主张、模板覆盖真实内容、没有证据的完成声明**。紫色、圆角、某个词或三项列表本身不构成缺陷；有真实理由就保留。

项目设计记忆只记录可核对条目，例如“DSH 右侧栏使用宿主字体和 alias tokens；保存区分草稿/期望/已加载”；每条带源文件与 hash。审美评价记录为偏好或待验证假设，不能变成系统事实。

### 7.1 技能路由与完成依据

- 任务类型触发对应短技能和参考文件；web-ui 不在纯后端任务常驻，anti-slop 不在代码字符串或引用材料中强制改写。使用项目自己的贡献规范，日志维护沿[现有指南](changelog-guide.md)。
- 保持现有七技能结构，核心正文目标不超过约 3 KiB，细则放按需 references；不把调研全文塞进 description、全局 systemPrompt 或每轮通知。
- 把产物级检查登记为 task requirements；命令/截图/人工评价分别保留来源。人工审美、语义保真未完成时为 unknown/awaiting review，不能靠结构检查自动 ready。
- 评价分别验证“是否该触发”“执行是否正确”“结果是否改善”，增加不该触发与允许 no-op 的反例，防止优化器通过多加载、多改写刷分。

## 8. Patchwork 原生管理 UI

保留现有五个顶级页签；在“证据”内部增加“本次 / 记忆 / 改进”子视图，不再新增一排主导航，也不做独立管理站点。概览只显示当前任务状态、被采用的少量记忆、待审改进和下一步动作。

```text
Patchwork                         当前项目 · 已连接
总览   机制   证据   日志   设置
              本次 | 记忆 | 改进

记忆：搜索 / 类型 / 有效性
使用 DSH 宿主主题 token       项目事实 · 已核验
来源 2 项 · 本次已采用        查看 / 纠正 / 忘记

改进：先读取宿主再修改插件 UI   待审阅
目标问题 / 修改差异 / 逐例结果 / 成本状态
仅对本项目启用                启用版本 / 拒绝
```

具体交互：

1. **记忆详情：**显示正文、条件、作用域、来源、验证时间、替代关系与本次使用原因；能跳到原始证据。纠正使用 expectedRevision；冲突保留双方，忘记展示派生影响。
2. **改进详情：**展示一处变更、来源案例、baseline/candidate 对照、未执行项、留出结果、未知成本与回退版本；区分项目默认版本与当前任务固定版本。来源证据不足时禁用“启用”，不能用一个总分代替逐项结果。
3. **实验控制：**提交前展示模型路由、隔离目录、预计上限与停止按钮；区分未启动/运行/取消中/未完成/等待审阅/已接纳/已启用/已撤回，不能把任务 ready 和经验 active 合成一个绿色状态。
4. **设置：**按实际范围展示部署能力、项目配置、已加载版本和草稿；记忆、模型提取、实验分别控制。单次实验授权不等于以后所有项目自动运行。
5. **宿主样式：**继续走 `sidebarRightTabs` 和公开 slots；复用原生 Button/Tabs/输入/提示/焦点行为。沿现有 `--dsw-alias-*`、`--dsw-font-family` 等 token，不新增独立主题开关、外部字体、全局 CSS 或装饰性 hero/KPI 卡。
6. **可用性：**320/480/800px 侧栏及浅/深色；长中文、长路径、键盘顺序、可见焦点、非颜色状态提示、读屏 label；空列表/损坏/未连接/无权限/冲突均有具体动作。批量正文读取与导出默认不发生。
7. **切换与并发：**切走后只显示锁定说明、卸载正文和草稿、停止请求；旧 response 不得覆盖新会话。UI 路由重复校验真实会话 composition、epoch 和版本，且复用现有 token/请求防护。
8. **读取范围与预算：**当前会话可切换 off/session/project；记录标明可见范围，并能查看“为何采用/为何未采用”。显示本次记忆 tokens/上限及计量可信度，不用数据库总条数暗示模型已经读过全部记忆。

“确认事实、启用经验、关联项目、导出正文”不暴露为模型可自行声明批准的工具操作。管理入口使用独立操作令牌/版本校验，并继承宿主现有权限；本机同用户拥有完整 shell 时仍不能声称存在不可伪造的人类身份或 OS 级边界。

## 10. 配置、迁移、隐私与可维护性

- **范围：**部署层给能力与上限，profile/project 层给实际开关和本项目预算，Session 层给本次授权。权限取约束交集；启用请求值不能覆盖部署禁用。记忆默认关闭，用户启用后提供 collect 模式；trial 默认关闭。
- **接收模式：**项目可配置新会话默认 off/session/project；记录来源决定默认私有性。模型不能通过参数将 session-private 转成 project-shared，或为其他会话切换模式。变更仅影响下次获准请求，不修改正在流式执行的请求。
- **位置：**拟将新数据置于 canonical home 下独立 `patchwork/memory/v1/`，按 instance/profile/project 分区。项目映射保存在服务端注册表，不跟随 repo clone 自动复制；路径 hash 只减少暴露，不是加密。
- **版本：**配置与 schema 都有版本；迁移前快照与完整性检查，失败只读或停用。新版本 DB 不交给旧代码直接写；回退程序经验只改激活指针，存储回退需匹配备份。
- **冷启动/热重载：**SQLite 是跨会话记录权威；恢复仅重建已核验范围和缓存，不恢复未完成实验授权。desired/loaded/draft 的 UI 语义沿用现状。
- **容量：**为候选数量、单条正文、检索结果、队列、证据引用和日志设明确上限；达限提示或淘汰未启用候选，不静默丢弃用户确认的事实。初始数值由 P1 数据确定。
- **导出：**默认只导出 schema/统计/版本与脱敏 manifest；正文与来源另行预览选择，不把整库加进普通诊断 JSON。完整 Session ZIP 的原文风险沿既有日志说明，禁止宣称自动全脱敏。
- **导入：**校验大小/schema/namespace、重复项和来源，始终进入 proposed；不得借导入触发远程读取、执行脚本或自动启用经验。未知范围拒绝，不回退 global。
- **撤销与日志：**日志使用 id/hash/结果码；未知敏感字段不入白名单。删除正文后诊断仍可说明删除发生过，但不能从错误堆栈、缓存、摘要、队列或旧索引取回正文。

## 11. 验收任务与真实实验

### 11.1 真实任务集

建立下面 12 类任务的固定输入与验收材料。每类准备独立的调优与留出实例，按代码/文案/布局族划分，避免相同题目仅换名字。首次先跑纯任务基线；它们是拟议实验，不是本轮已完成结果。

| 任务族 | 真实任务 | 必须核对 |
|---|---|---|
| M1 新会话恢复 | 新 Patchwork 会话修改同一插件 | 能找到经核验的入口/token；按本次任务重新验证，不复用旧 ready |
| M2 纠正与撤销 | 将“全项目改动”纠正为“本次只调研指定资料” | 当前 task 立即收窄；旧经验不扩大授权，不把一次限制升级为永久偏好 |
| M3 过期与矛盾 | 改测试脚本/设计源文件，再查询旧记忆 | 检出 hash 变化或冲突，不执行旧命令后宣称成功 |
| M4 不复活 | 删除记忆后恢复旧 Session、导入旧档、等待异步提取返回 | 正文与派生结果不重新出现；恢复需新确认 |
| I1 能力隔离 | standard、Patchwork、切走、fork、并发会话/项目/profile | 工具、技能、Web/API、缓存、上下文均不越界；旧引用拒绝 |
| U1 插件界面 | 在真实隔离 DSH 中完成配置、查证据、纠正记忆、回退经验 | 宿主入口/主题/窄侧栏/键盘/状态及真实数据一致 |
| U2 去模板 UI | 将一份套模板的插件界面改为宿主一致的任务界面 | 去掉阻碍内容的装饰，保留真实功能；人评与行为结果分开 |
| U3 正常界面反例 | 对已有清晰一致的页面做小范围修复 | 不因“去 AI”重设计整个产品；修复范围与任务一致 |
| W1 事实保真 | 编辑含数字、否定、条件、日期与未完成状态的说明 | 不编例子、不强化确定性、不把计划写成实现；盲评清楚度 |
| W2 发布文档 | 根据真实 diff 写 README 与更新日志 | 使用当前版本/命令、说明限制；纯调研不冒充新增功能 |
| C1 失败与清理 | 修复已知失败，同时清理冗余代码 | 非零退出/超时不能通过；错误、安全和兼容路径保留 |
| E1 候选控制 | 提交看似提分但泄漏答案、改裁判或只省成本的候选 | 不接纳；预算耗尽/缺留出/证据 unknown 不变成 passed |

### 11.2 对照与指标

三组：A 现有任务/技能、不用新记忆；B 仅有效项目事实检索；C 在 B 上使用一个已审候选经验。模型路由、快照、预算一致，每次重建实验数据；测试副本可写，参考与裁判只读。

探索可先跑子集，但正式对比应覆盖 12 类留出任务并重复，报告所有运行。例如每类一个留出实例、三组各重复三次，即至少 108 个任务 Session，尚未计调优；必须单独批准足够预算。不能把这些任务混进 12 Session 的探索限额后宣称完整验证。

指标分开展示：召回正确性/遗漏/无关注入、来源与事实支持、纠正生效、越界次数、正常 no-op、功能/失败路径、文案信息保留、任务完成率、人工 UX/清晰度、维护审阅、tokens/cache、用量与费用状态、延迟。没有可验证来源的结果标记 unknown；不压成一个“智能程度总分”。

错误按提取、更新、检索、预算裁剪、reader 和实际行动分阶段归因；给定人工核验 oracle 证据的对照用于分离读错与没召回。拒答另测，不能拿排除了无答案题的检索汇总替代。模型 judge 保留提示/版本、异常与 unknown，抽样人工复核；问答分、选择性遗忘分与真实任务成功、物理删除分别报告。

### 11.3 硬门槛

隔离测试中的任何越权、删除后复活、候选污染裁判、已知功能回归或事实新增/丢失都阻止接纳。代码/结构测试和 UI 自动化先跑，再在隔离真实 DSH 执行工具和用户路径；mock、一次截图、档案 lint 不替代真宿主证据。

请求级负测使用无敏感意义的唯一标记，捕获实际发送请求，覆盖 Patchwork → standard、同项目其他会话、其他项目/profile、重启/fork、重试、压缩与 prepared route；不能只断言工具列表为空。另测恶意文档/工具输出诱导记忆转正或扩大范围，以及无命中/短中文查询。

补充共享与预算测试，不能用“所有会话都拒绝读取”来冒充隔离正确：

- A 私有记录对 B 不可见；A 明确共享的事实可被同项目、project 模式的 B 相关检索读到，但不能据此打开 A 的私有来源、继承 A 的行动要求或 ready。
- B 设 off/session 后不读取项目共享事实；A、其他 project 模式会话仍正常使用。A 切走、取消请求不停止 B；未知范围与其他 Agent 不能借共享路径读取。
- 同项目 A/B 有冲突任务要求时分别遵从当前任务；项目记忆更新在下一次请求核验，流式中途不变，过期写入 CAS 拒绝，不直接改另一会话 task。
- 连续 100 步、重复 search/get、详情翻页、同条目多次命中后，每次实际请求中的可识别记忆投影仍在动态预算内，不能在历史或 toolHistory 里累积。
- 候选池大于投影额度时，裁掉的条目不进入 sent/已提供集合；下一次有预算仍可选。命中、采用和行为成功各有证据，不互相冒充。
- queued 后立即 search、committed 后 get、索引落后、超时/取消/删除后迟到返回分别测试；用户看到的写入状态与真实提交/索引水位一致，读己之写不绕过可见性。
- 旧事实被更正后再导入旧材料，分别问现在与历史；当前不被旧导入覆盖，历史有明确时态。删除后重建词法/向量索引、重启和恢复，不复活正文或摘要。
- 窗口临界、输出预留改变、工具定义增大、路由切换、中文 token 估算不确定时，预算会缩小或停用；原生已有任务与证据不因记忆装载被删除。
- 压缩、恢复、fork 与 Agent 切换后，不复活旧私有正文、不复制重复记忆视图；token/cache 计量和占用显示与实际请求一致。
- A 接纳项目经验 v2 时，B 正在执行的任务仍绑定 v1；后续匹配的新任务可读取 v2，其他 Agent 不获得。撤回 v2 只阻止依赖它的后续采用，不重置工作树或取消无关任务。
- 纠正、失败、开销优化与成功方法候选保留真实来源类型；未运行的试验、未知验收、模型自评和私有材料不能冒充真实训练/留出案例。启用后失败不自动扩大预算启动付费实验。

## 12. 分阶段执行顺序

每阶段先交可验证增量，不把整套系统一次性接到主 DSH。

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| P0 宿主与范围合同 | profile/project/可见性解析、请求投影与计量能力探针、实际运行时 SQLite/worker 兼容表、固定测试案例 | 私有/共享正反例与实际请求切换负测通过；无公开安全投影则禁用注入并给出上游扩展提案 |
| P1 记忆底座 | schema、事务/CAS、来源与有效时间、写入回执/索引水位、读己之写、纠正/删除/冲突、分层词法检索、会话读取模式与原生管理视图 | 并发/重启/损坏有明确状态；当前/历史查询正确；删除后重建不复活；授权共享可读、关闭会话不影响其他会话；中文短词可用 |
| P2 有界使用与质量 | 仅在 P0 门槛达标后接入请求投影；候选/准入/发送分离、动态预算、100 步累积验证、任务引用、技能路由、UI/写作/代码验收 | 每次实际请求符合动态预算；分阶段错误归因；M/I/U/W/C 基线与负例完成；B 对 A 的逐例结果公开，无虚报收益；OCC/EPR/OP 回归 |
| P3 学习实验器 | v2 评价器、候选版本、隔离 runner、预算、逐例对照、任务版本绑定、采用反馈、停止/审阅/回退 | 来源类型真实；repair 基线失败可正确记录；伪造/缺失/污染/取消档案拒绝；C 对 B 真任务留出完成；新版不热替换其他任务 |
| P4 稳定与推广 | 配置/数据库迁移、包兼容、故障恢复、使用文档与用户可见更新日志 | 完整回归与真宿主报告；明确未验证项；只推广本项目已审版本，跨项目仍显式选择 |

优先做 **P0 → P1 → P2**，让“能记、能纠正、能忘记、只对正确会话生效”先成立。P3 以这些边界为基础，不抢先实现自动写 prompt 的学习循环。若请求投影受宿主限制，P1 管理及候选收集可交付，模型自动使用明确保持关闭，不能称整套能力已上线。
