# Patchwork 日志

更新：2026-10-31。

## 查看与导出

1. 在 DSH 新任务的 Agent 选择器中选择 **Patchwork**，再执行任务。
2. 打开右侧栏的“开始”→ **Patchwork** → **日志**。
3. 按机制或级别筛选，也可搜索事件、原因码及调用指纹。扁平列表显示中文事件、级别和时间；
   点击记录，在下方查看执行结果、耗时与计量。“关联指纹与原始元数据”进一步展示宿主序号 `seq`、关联字段和 JSON。
4. 点击“导出诊断元数据”，下载 `patchwork-diagnostics.json`。

导出只包含该会话最近的诊断元数据，遵循与面板相同的 200 条上限；不是完整会话导出，
也不包含 OP/EPR 原文归档。空筛选不表示原生会话中没有更早的记录。
可见面板每 2 秒更新；连接中断时保留最后快照并暂停导出，不能把旧快照当作实时状态。
DSH 保留的后台会话或隐藏页签不挂载业务面板：轮询与待返回请求停止，证据和未保存草稿卸载。
重新显示后重新读取该会话状态；隐藏面板前请保存需要保留的设置草稿。

## 记录内容

四个机制与运行时共用 `schemaVersion: 1`，记录类型为
`plugin:patchwork/diagnostic`，使用宿主的非上下文插件记录接口：

| 机制 | 记录 |
|---|---|
| runtime | 运行时加载及安全诊断 |
| AF | 融合开始、成功、失败、跳过；耗时、退出码、输出字节数 |
| OP | 打包与召回；句柄、原文 SHA256、字节数、行数及分页偏移 |
| EPR | 候选/收据决策、固定原因码、本地或模型路由、耗时、实际报告的 usage、压缩前后字节数 |
| OCC | 计划边界、经济判定、压缩开始/成功/no-op/失败、续跑；估计与实际节省分别记录 |

高频无关操作（例如 EPR 遇到非 shell 工具或低于阈值的输出）不逐条记诊断。
OCC 的 `state.json` 仍是可恢复的决策状态，不代替事件历史。

诊断使用字段白名单，不复制 system prompt、用户消息、完整命令/参数、工具输出、
HTTP headers 或任意异常文本。调用 ID、root 调用 ID、命令、provider 和 model 使用
SHA256 指纹；可用相同的指纹关联 AF、OP、EPR 及面板工具证据。
指纹便于关联，不是加密，也不能使低熵输入不可猜测。
来源 hash、OP 句柄及数值计量仅按限定格式收录；从持久历史恢复时再次校验字段。

`warn`/`error` 同时使用宿主 `ctx.logger`，只传固定的机制、事件、原因和错误码，
不传原始 Error。记录失败不会遮蔽工具结果、改变机制决策或新增模型请求。

### 任务记录与诊断记录分开

融合升级新增 `plugin:patchwork/task`，这是任务 checkpoint，不属于上面的诊断字段白名单。
它保存有界标题/验收标签、工作与参考对象绝对路径、产物版本/文件 stamp、来源类型、
callId/退出状态和任务内候选引用；不主动复制完整命令、工具参数、输出或提示词。
标题/路径本身仍可能透露项目信息；常见秘密的预览遮盖不是任意内容全面脱敏，
不能把诊断日志的隐私承诺直接套到完整任务记录或宿主 ZIP。

任务 records 标记 `ignorable`，不会自行进入 `deriveMessages()`；显式任务工具结果、
pre-step 短投影与 OCC 续跑摘要会按设计进入 Patchwork 模型上下文。
每份 checkpoint 最多100000 bytes、24项验收/产物、32份近期回执，原生历史保留仍由宿主管理。
完整宿主 ZIP 包含 task records；“导出诊断元数据”仍只导出诊断，不能替代任务状态或完整历史导出。
冷恢复损坏/缺失时显式阻塞，不从不完整记录猜测已通过或权限。

## 原生持久化与兼容宿主

支持 `appendPluginRecord` 的宿主将诊断写入当前 DSH Session，随宿主持久化路径保存，
事件标记为 `ignorable`，不进入 `deriveMessages()`，也不更改工具 schema 或 token 计量。
优先解析插件依赖，然后解析启动宿主的 Session API，并匹配实际 Session 类，
避免不同包副本的私有品牌不兼容。

| 面板状态 | 含义 |
|---|---|
| 原生记录 | 记录已追加至宿主 Session；磁盘刷新与保留遵循 DSH |
| 内存记录 | 宿主没有可用的原生插件接口；仅在当前进程保留最近 200 条 |
| 原生日志写入失败 | 本轮原生追加失败，保留有界内存记录并显示失败次数 |

UI 与诊断导出最多显示最近 **200 条**；首次恢复最多扫描尾部 **5000 个宿主事件**，
之后按序号增量读取。因此，尾部 5000 个事件以外的旧诊断不会自动出现在面板。
原生历史不受这个预览上限裁剪。已降级到内存的记录不会在接口恢复后自动回填。
本轮真实宿主验证为 DSH **0.2.1-rc.2**；仓库的 0.2.0-rc.2 依赖基线不保证提供此接口。

## 隔离与安全边界

- runtime 只由 Patchwork preset 装载。写入前、异步完成后及排队落笔前检查当前真实组合；
  standard 或已切走的旧工具引用不能继续记录 Patchwork 诊断。
- 读取与导出要求页面 token 及目标会话实际处于 Patchwork。HTTP 响应为 `no-store`；
  导出中的 session ID 也使用指纹。根 Web 桥接不注册全局模型内容采集器。
- 面板随当前会话切换，离开 Patchwork 会卸载日志/证据及草稿，并取消未完成导出；
  切回后才能重新读取。这个限制是应用内授权，不是多用户文件权限系统。
- Web 证据预览额外遮盖常见 API key/token/password、Bearer、认证/Cookie header、
  URL basic-auth 和私钥格式。这是补充防御，不承诺识别任意秘密。
- OP/EPR 的 `objects/` 继续保存逐字原文，用于 hash 校验和证据召回；
  诊断升级不会改写或自动删除这些原文。DSH 原始工具历史同样可能包含敏感内容。
  分享原文或宿主完整会话导出前，需要单独审查内容。
- 同一 OS 用户及拥有相应文件读取权限的工具仍可能直接读取文件；
  会话目录分隔及 POSIX mode 不等于 Windows 独立 ACL。

## 兼容侧挂文件

以下路径相对 `DSH_HOME/patchwork/`，只保留兼容元数据：

| 文件 | 当前内容 |
|---|---|
| `observation-pack/<sessionId>/ledger.jsonl` | OP 白名单记录；调用 ID 为指纹 |
| `evidence-preserving-reducer/<sessionId>/journal.jsonl` | EPR 白名单决策；无原始命令或动态异常字符串 |
| `patchwork-online-context-compact/<sessionId>/state.json` | OCC 决策状态，独立于日志 |

新写入的 ledger/journal 每个当前文件最多 **256 KiB**，另保留一个 `.1` 轮转备份。
按文件路径在单进程内串行追加；不宣称跨进程事务。该策略不轮转 `objects/`，
也不清理升级前的其他备份或原文。已有旧记录不会被自动重写脱敏；超过阈值时
旧文件可能进入 `.1`，其内容和大小应作为历史数据单独检查。
