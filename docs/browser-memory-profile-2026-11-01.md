# 浏览器内核与内存短测

> 本文保留资源管理改动前的测量基线；后续并发/回收策略已实现，见[浏览器资源管理](browser-resource-management-2026-11-01.md)。下文「当前」描述的是本次基线采样时的实现，不是新版策略。

日期：2026-11-01。平台：Windows x64，实际浏览器为 Microsoft Edge `156.0.4314.58`。这是同一台机器上的隔离短测，不是内存上限、长期泄漏检测或模型任务成绩。

## 当前实现

- 默认后端为 Chromium，Windows 通过 Playwright 启动独立 Edge 进程，其他已配置平台使用系统 Chrome。使用临时浏览器上下文，不连接用户已打开的浏览器、不复用用户登录目录。
- 原生内核主要是 C++：Chromium/Blink 负责页面平台与渲染，V8 执行 JavaScript/WebAssembly。参考 [Blink 接口实现说明](https://www.chromium.org/developers/web-idl-interfaces/)、[V8 官方说明](https://v8.dev/docs)和 [Edge Chromium 官方说明](https://learn.microsoft.com/en-us/microsoft-edge/web-platform/site-impacting-changes)。
- Patchwork 控制层为 Node.js / JavaScript（`src/browser/*.mjs`），侧栏为 React JSX 与 CSS（`src/client/BrowserPanel.jsx`、`panel-styles.mjs`）。本轮没有改写浏览器原生内核。
- 浏览器按需启动；每个 Patchwork Agent 独立进程实例，每会话最多 8 个标签。隐藏侧栏停止画面订阅，浏览器本身可以继续运行。用户休眠标签会关闭对应页面，只保留本进程内的恢复 URL；关闭浏览器或释放 Agent 会关闭浏览器进程。

## 测量方法

直接运行当前 `BrowserSession`，测试 Agent 授权来自明确的宿主注册表夹具，使用独立的目录、浏览器和本地 HTTP 服务；不启动主 DSH、不接管用户浏览器、不请求模型。页面含 12 个设备卡片、120 行记录和 640×140、4 fps 的 Canvas 动画，视口为 1280×800，没有外部网络依赖。

Windows CIM 按本次 Node 的进程后代识别 `msedge.exe`，只统计本次浏览器进程；采样 PowerShell 不计入浏览器或 Node 主进程。每种状态稳定等待后采样 3 次，各指标取中位数。控制器仍可能有异步 GC、浏览器仍可能有缓存，因此顺序短测不代表稳定长期占用。

- **私有驻留内存**：`Win32_PerfRawData_PerfProc_Process.WorkingSetPrivate`，已驻留物理内存中的私有页。
- **进程工作集合计**：同一组进程的 `WorkingSet` 相加，共享页可能被重复计算，不能视为独占物理内存。
- **私有提交**：`PrivateBytes`，包括未必驻留物理内存的私有提交，不等于当前 RAM 占用。

## 如何解读

本地轻量页的单会话成本可控，但不是轻量 WebView 的资源规模。多 Agent 各自启动浏览器会重复浏览器实例的固定成本；复杂外部站点、视频和 WebGL 的占用须另外测量。休眠后本轮私有驻留从 344.6 降至 166.9 MiB，仍高于首次单页，不能承诺立即回到冷启动水平。

当前的 8 标签限制不是 RAM 硬上限；没有全局浏览器内存预算或已经实现的自动空闲退出策略。不以关闭多进程隔离、sandbox 或串用用户浏览器来降低占用。可继续评估用户可配置的空闲回收与全局并发预算，但本次仅做测量，没有改变运行策略。

原始采样、中位数、引擎版本、范围和清理结果见机器可读记录。本轮浏览器均已关闭，测试目录已删除；短测不能证明没有长期内存泄漏。Camoufox 未运行，不给出其内存结论。
