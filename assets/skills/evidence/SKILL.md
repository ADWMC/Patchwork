# 完成证据

跨步骤交付需要逐项验收时，`patchwork_task` 可用就登记与用户要求一致的验收；小型只读结论可直接给来源与边界。工具不可用时以实际来源、命令和产物说明验证范围，不虚构调用：

1. 代码：check 调用宿主 pwsh/bash，保存实际 callId、退出码和当前版本；isError=false 或无退出码为未知，不补 0。AF then_run 失败不被外层写入成功掩盖。
2. 文档/写作：artifact 登记真实文件，artifact 类 check 可核长度/锚点；这只证明结构，事实、读者和表达仍需语义审查，assessment 的模型判断不自动通过。
3. 调研：每个关键主张区分支持、矛盾、未知；来源须对应实际题名、版本与相关片段，不能因搜到相似结果就宣称支持。不足则补查或限缩结论。
4. 全量任务：coverage 登记每个单元，不以成功数替代全集。方法、指标、真实客户端、目标实例遵守原要求；裸 API 不代替客户端，整段耗时不代替首字时间。

输入/产物或要求变化后，相关验收 stale；新旧异步结果不混用。确定性方法错误首次出现就诊断；偶发失败按原因决定是否重试，别无差别整批重跑。明确取消、失败、部分完成与阻塞。

**禁止**：「应该好了」「代码已生成」「看起来正常」；用道歉代替跑命令；只跑新写测试却说「全过」。

交付前按 `standards` 核使用文档与更新日志是否覆盖本任务；文件存在不等于内容完整。不适用给具体理由。旧验证与本轮检查分开，不把历史测试数写成刚跑的结果。

只报告实质残余风险、未知和必要的下一步；没有就直接结束，不加固定尾句。

收到 `[pw:evidence]` → 检查当前任务的真实缺口，按任务类型补验收，不机械跑无关 shell。工具结果提示与 UI 状态不能硬拦最终文本，汇报必须自己保持一致。姿态 → `collaborator`。
