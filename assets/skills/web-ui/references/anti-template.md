# 去模板味复核

用于新页面首稿、整体改版，或用户明确指出「AI 模板味」时。它是设计判断与截图复核流程，不是固定禁用色表。先满足功能、品牌与宿主约束，再消除无依据的默认排版。

## 先锁定设计依据

从用户给的参考、产品现有页面、组件、token、字体和真实内容里取证。对外部参考只提取要保留的**组织原则**（例如密度、对齐、信息关系、材质），列出必须改掉的对象与文案；不复制品牌、截图或完整布局。没有依据时，标明推断，并选择一个与主任务有关的方向。

动手前在工作记录里回答四件事，勿输出成页面副标题：谁在反复使用；第一眼要看什么或做什么；内容应按什么关系组织；哪一个视觉决定只有这个产品会做。决定应落到布局、比例、字阶、颜色角色和控件状态，而不只是命名一种风格。

## 检查结构，而非只查表面特征

| 首稿征兆 | 要问的问题 | 可尝试的改动 |
| --- | --- | --- |
| 全宽说明横幅加一排等权卡片 | 全局操作、单项操作、状态是否真的同级？ | 按操作频率、对象关系或使用场景重排；把全局控制放在工具区。 |
| 每项同时有图标、彩色边框、徽章、文字状态、开关 | 哪些信息重复描述同一状态？ | 保留最清楚的一个主要状态表达，其余只在需要辨别时出现。 |
| 大面积渐变、发光或套用品牌色 | 它是否帮助辨认产品或理解状态？ | 先用灰度验证层级，再让少量颜色承担明确角色。 |
| 组件形状、间距、字重完全一致 | 这种整齐是否掩盖重要差异？ | 用尺寸、留白和内容密度表达真实优先级；不为不对称而不对称。 |
| 页面解释「我们做了什么」或重复操作说明 | 文字是否帮助当下完成任务？ | 删除制作说明；只保留必要标签、状态、错误与下一步。 |

卡片、深色、圆角、系统字体本身不是错误。只有在它们成为未经任务证明的默认答案时才改。不要靠随机换色、加纹理、换一组图标或编造数据制造「独特」。

将首稿暂时去色、隐藏品牌名后再看：若它仍可直接套到任意别的产品，检查是否漏掉了对象之间的真实关系。与本项目既有页面对照，不要把上一次的构图当成下一次的默认方案；组件级修改不另造整页结构。

## 首稿必须复看

在目标桌面和手机尺寸看实际截图。先说出首屏主对象，并指出确实观察到的模板化重复；若发现问题，至少修改一处**结构或信息层级**后再截图。核对功能、焦点、状态和窄屏没有退化。自动扫描可发现占位文案、硬编码默认色等线索，但无法判定页面是否适合这个产品；审美结论留给用户复核。

本轮触发案例：家居控制台的四张等权设备卡、顶部说明区、重复状态标签和桌面下半屏空白，虽然交互测试通过，仍被用户判为模板化。这个案例是失败证据，不是所有控制面板都应采用的替代版式。
