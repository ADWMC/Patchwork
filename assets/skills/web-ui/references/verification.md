# Web UI 验证矩阵

用于实现、评审和交付。每项只在目标界面适用时检查；记录目标视口、主题、操作路径、证据与未覆盖项。静态检查提出线索，浏览器行为与截图提供另一类证据，用户审美偏好仍须由用户判断。

| 类别 | 代表性检查 | 证据 |
| --- | --- | --- |
| 主任务 | 从入口执行核心动作，检查提交、保存、取消、重试后的真实状态 | 操作轨迹、接口/文件结果 |
| 状态 | 初始、加载、空、部分成功、失败、恢复与未保存变化 | 对应渲染和交互结果 |
| 内容 | 按 schema 注入最长/最短、缺省、零/单项/大量记录、数字和翻译样例 | 目标容器截图、溢出或裁切位置 |
| 尺寸 | 实际嵌入宽度、窄屏、文本放大、支持的浅深色 | 各尺寸与主题的截图 |
| 可用性 | 语义控件、可见焦点、键盘路径、表单标签、图标名称、错误下一步 | 人工操作与可用的自动检查 |
| 视觉 | 主角、层级、对比、字体、裁切、装饰是否服务内容 | 首屏和关键状态截图，保留/修改判断 |
| 运行 | 项目原有构建与测试；页面性能或无障碍工具仅在可运行时使用 | 命令、退出码及具体发现 |

新页面至少复看一次截图；明显缺陷修正后再看。动态或 3D 主视觉须实际操作。审查发现给出位置、触发条件、用户影响、证据和建议；自动评分不证明视觉质量，也不代替核心任务验收。无法运行或看图时，明确未验证的维度，不以“看起来不错”补结论。

可选包 `@patchwork/browser` 安装且用户授权当前会话后，才提供 `patchwork_browser` 工具；每个授权 Agent 按需启动独立的无痕浏览器，不连接宿主浏览器的 CDP 端口。先写出页面，再用 `navigate`、`click`、`resize`、`reload` 和 `screenshot` 验证。可直接打开当前会话工作目录内的 `file://` 页面；工作目录外的本地文件被拒绝。工具不可用时说明原因，再用现有命令行验证。

浏览器返回动作回执与截图的尺寸、代次和哈希。可传 `expected: { selector, text }`、`{ selector, visible }` 或 `{ urlIncludes }` 验证动作后验；`unasserted` 只说明没有断言，不能说验收通过。重复无进展时刷新观察并改变方法，不机械重试。`capabilities` 查看当前真实能力和安装状态；`health` 只使用本地 probe 检查页面、同源 iframe、Worker、请求头与 Canvas，不代表出口/TLS/WebRTC或任意网站检测已通过。`trace` 仅含有界动作元数据。侧栏实时流不自动进入模型上下文，Agent 仍须显式截图。

用户接管后只观察，不能借切环境、重连或恢复标签夺回控制权。焦点、标签或代次变化后要重新观察；不得用系统剪贴板快捷键搬运宿主数据。上传、下载、录像和 trace 文件导出由用户面板显式操作；下载需单次授权，录像是会跳帧的采样视频。有效文件与交付哈希出现前，不把“任务启动”“录制中”或路径字符串当作已交付证据。

参考做法：OpenDesign 的设计系统包让 token 与组件产物可追溯；Emil Kowalski 的 `break-ui` 强调真实边界数据。这里采用验证方法，不复制其技能正文。来源：https://github.com/nexu-io/open-design/blob/main/design-systems/README.md ，https://github.com/emilkowalski/skills/blob/main/skills/break-ui/SKILL.md
