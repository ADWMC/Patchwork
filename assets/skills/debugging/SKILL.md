# 调试与根因

先记录实际症状、触发输入、环境、预期和观察结果；不能复现时标明证据来自日志、用户描述还是推断。按入口、状态所有者与副作用边界缩小范围，查看近期相关变化和原有测试。不要用猜测替代失败样本。

提出可证伪的原因假设，选能区分假设的最小检查；发现确定性方法错误就调整方法，不盲目重试。性能回退先固定指标、负载和环境，再判断变化是否显著。多组件故障或无法复现时读[边界取证](references/failure-analysis.md)。

修复应针对已证实原因，并保留现有兼容、安全和取消语义。验证原失败路径与相关回归；只报告实际运行的命令、退出码和未覆盖情形。用户只要求定位时交付发现与证据，未经要求不扩展到重构。
