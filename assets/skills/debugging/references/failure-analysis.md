# 边界取证

用于无法稳定复现、跨进程/组件或性能回退。先写清失败发生在哪个边界：输入解析、状态读取、转换、持久化、网络、渲染或回调。每次实验只改变一个可解释因素，并保留原样输入、时间、版本和原始错误。

对两个可疑组件，分别记录调用前后的值和副作用：输入是否到达、返回是否成功、错误是否被包装、取消或重试是否改变顺序。日志没有字段不等于字段为零；不要通过扩大日志中的秘密与提示词内容来“补证据”。

性能基线至少说明任务、指标、采样数、缓存状态与机器条件。只对可比样本算差异；没有基线时先建立基线，不宣称加速。修复后重跑原样输入，并在边界上加足以防止回归的检查。

## 区分原因的最小实验

| 观察 | 下一项检查 | 尚不能推出 |
| --- | --- | --- |
| Windows `EPERM` | 记录操作、目标路径、进程权限、文件占用与原始错误；在相同条件下重试最小操作 | 一定是 ACL，或换目录就算修复 |
| 只在重试后出错 | 对照每次调用的输入、取消信号、状态版本和副作用顺序 | 单纯增加重试次数能解决 |
| 只在特定配置出错 | 比较实际生效配置、默认值及加载顺序 | 配置文档写法就是运行值 |
| 延迟变大 | 固定同一负载与缓存状态，分别测调用、等待、模型和工具耗时 | 单次总耗时能证明稳定回退 |

先做能排除至少一个假设的检查。若两个假设都能解释同一日志，写明还缺哪个可区分观测；不要把日志中的相邻事件硬连成因果。实验可能改动文件、服务或持久状态时，先核任务范围与隔离环境。

## 验收记录

交付时用三栏说明：**原失败输入**（原样或脱敏后的可复现形式）、**修复证据**（实际运行的命令/测试及结果）、**未覆盖范围**。测试通过仅证明该测试路径，不能替代平台、并发、取消或旧数据兼容检查；这些风险与修改面相关时才扩展。若用户只要求定位，给最可能原因、反例与下一项检查，不把未经执行的修复写成已完成。
