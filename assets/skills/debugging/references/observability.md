# 可观测性与二分排查

来源参考：[Google SRE Book](https://sre.google/sre-book/table-of-contents/)、[git bisect](https://git-scm.com/docs/git-bisect)、[Brendan Gregg](https://www.brendangregg.com/) 。

## 先固定现场

记录：症状、触发输入、环境、版本、预期、实际、时间线。不能复现时标明证据来自日志、用户描述还是推断。

## 三类信号

- **日志**：事件、错误码、请求 ID、时间顺序；注意采样和脱敏。
- **指标**：延迟、错误率、吞吐、资源；先看趋势和分位数，不看单点。
- **追踪**：跨服务调用链、耗时分布、失败点。

关联信号用请求 ID/时间戳，不靠猜。区分“症状”与“根因”；先确认影响面，再决定回滚或热修。

## 二分

- 代码：`git bisect` 找引入提交；每次验证可复现的失败。
- 配置/依赖：一次只改一个变量，记录结果。
- 输入：缩小到最小失败样本；删除无关步骤。
- 环境：对比正常/异常环境的版本、权限、路径、网络。

## 验证

修复后重跑原失败路径，再跑相关回归；报告实际命令、退出码和未覆盖路径。性能问题先固定指标、负载和环境，再判断变化是否显著。
