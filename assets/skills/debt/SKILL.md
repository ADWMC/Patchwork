# 妥协账本

代码里的有意妥协按 `shortcut: <限制>, <何时升级>` 登记。本技能把它们汇总成一张账本，让妥协不会悄悄变成永久。

## 扫描

1. 用 `patchwork_code` 的 search 动作搜 `shortcut:`（或 grep `shortcut:`），覆盖源码与脚本；跳过依赖与构建产物。
2. 每条整理为：`文件:行号 — 限制 | 升级条件`。原文照抄，不概括。
3. 逐条判断升级条件是否已满足（依赖已就位、场景已变化、限制已被触发）：满足的标“可升级”，未满足的标“等待条件”，无法判断的标“未知”。没有证据不说“应该升级了”。
4. 按“可升级 → 等待条件 → 未知”排序输出；没有登记就明说没有，不要编造。

## 边界

- 只读报告：不修改代码、不删除登记、不自动升级。
- 登记是作者当时的有意决定；报告只核对条件，不评判当初的选择。
- 本账本与改进管线相接：反复被触发或阻塞验收的登记，可用 `patchwork_task` candidate 记录任务内候选，走受控改进；不在本技能里直接改规则。
- 旧的 `ponytail:` 前缀是早期约定的拼写，发现时按同格式纳入并提示可改写成 `shortcut:`。
