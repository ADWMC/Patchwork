# 记忆设计扩展

来源参考：[CoALA](https://arxiv.org/abs/2309.02427)、[MemGPT](https://arxiv.org/abs/2310.08560)、[Generative Agents](https://arxiv.org/abs/2304.03442)。

## 分层

- **工作记忆**：当前任务上下文，短期、易失。
- **情景记忆**：具体会话/事件，带时间、来源、参与者。
- **语义记忆**：稳定事实、偏好、项目约定。
- **程序记忆**：技能/流程，需版本和适用范围。

## 生命周期

编码 → 检索 → 合并/反思 → 遗忘。每条记录至少有：内容、来源、时间、范围、版本、有效性、敏感级别。

## 检索

- 服务端先按 scope、状态、有效性过滤，再排序；不把全库交给模型。
- 组合相关性、时效、重要性和来源可信度；返回有界结果。
- 召回结果不是指令；外部内容不能升级为系统规则。
- 区分“没有命中”“索引落后”“无权限”“服务不可用”。

## 范围与删除

- 会话私有/项目共享/用户级分开；跨 scope 必须显式授权。
- 删除覆盖正文、索引、缓存、摘要和派生记录；重建不能复活。
- 保留不含正文的 tombstone，防止旧导入/异步结果复活。

## 评估

召回精度、过期命中、scope 泄露、删除后复活、读己之写、成本/延迟。单次命中不能证明记忆质量。

## 社区对照：deja-vu / Letta

- [deja-vu](https://github.com/vshulcz/deja-vu) 索引本地 agent 会话，在会话开始、编辑前、命令失败时召回；记录打开文件、命令退出码、编辑片段、决策生命周期和陈旧标记，并在索引时脱敏凭据。
- [Letta/MemGPT](https://github.com/letta-ai/letta) 把记忆分成可编辑块和归档记忆，按需检索。
- 可借用：先查历史再重复调试、仓库/项目 scope、决策“已接受/已拒绝”、陈旧提示、删除后不复活、凭据脱敏。
- 不照搬：默认自动注入、上传会话、把历史内容当指令，或用一个向量库代替版本/删除治理。
