# 受控改进

先找到实际失败、纠正或未验证回执；没有来源就只能提出调查问题，不能宣称“学会了”。`patchwork_improvement` 可用时，按 incident → propose → experiment 记录来源、适用触发、候选动作和回退点。将规则、记忆策略、工具流程、UI 提示分开，不把个人偏好写成通用规则。

实验固定模型、宿主、工具、初始任务和预算；分调优/留出集，比较基线与候选的正确性、隔离、成本与退化。结构检查不证明真实效果。评测设计或使用已有基准时读[实验准入](references/experiment.md)。

`trial`、`approve`、`rollback` 需宿主确认通道里的用户确认和当前 revision；即使记录成功，也不代表运行规则已自动激活。未得到确认时交付候选和证据，不能以当前会话文本自行批准。
