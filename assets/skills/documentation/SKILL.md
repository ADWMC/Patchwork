# 产品与工程文档

确定读者要完成的操作、适用版本和现有文档约定。以当前实现、配置、命令和实际验证为依据；把规划、已实现、已发布和未验证分开。外部项目先遵守其原有格式，不照搬 Patchwork 的日志类别。

README/指南回答“怎么用”，更新日志回答“什么变化、谁需要动作”，验证报告回答“如何证明”。同一事实不在三处重复长篇说明。写前核实际命令、默认值、错误路径与兼容范围；写后检查链接、最小使用路径及数字、否定、时间和因果。发布或迁移内容读[版本与迁移](references/release.md)。

用户只要草稿时交付草稿，不把草稿写成已发布。文字表达可按需用 `anti-slop`；结构或文件存在不能证明读者能完成任务。

扩展阅读：[文档四象限](references/diataxis.md)。
