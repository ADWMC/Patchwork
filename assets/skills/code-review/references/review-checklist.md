# 评审清单

来源参考：[Google Engineering Practices · Code Review](https://google.github.io/eng-practices/review/)、[OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/)、[OWASP Cheat Sheets](https://cheatsheetseries.owasp.org/)。

## 先定范围和基线

读完整差异、调用方、配置、测试和迁移；未跟踪文件与生成物按实际影响纳入。不要只扫新增行。

## 检查顺序

1. **正确性**：边界、空值、错误分支、状态转换、并发。
2. **安全**：输入验证、授权、秘密、路径/SSRF、注入、外部内容信任。
3. **数据**：迁移、兼容、回滚、幂等、事务。
4. **依赖**：新增依赖是否必要、来源/版本/许可证、lockfile、已知漏洞；不要为了一个小功能引入大依赖。
5. **行为**：取消、重试、超时、部分成功、资源释放。
6. **测试**：是否覆盖真实失败路径；断言是否有效。
7. **可维护性**：职责、命名、重复、接口稳定性。
8. **性能/可观测性**：只在有证据或明显风险时提出。

## 发现格式

触发条件 → 实际影响 → 证据/文件行号 → 最小修正方向 → 严重程度。不能定位时标待核；不要把风格偏好写成 bug。

## 约束

默认只给发现，不擅自修改被评审代码；用户明确要求边审边修时再实施，并区分已修复/未修复。没有发现也报告检查范围和未运行路径。
