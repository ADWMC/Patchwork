# 写作质量与反模板

来源参考：[Microsoft Writing Style Guide](https://learn.microsoft.com/en-us/style-guide/welcome/)、[GOV.UK Style Guide](https://www.gov.uk/guidance/style-guide/a-to-z-of-gov-uk-style)、[Google Developer Documentation Style Guide](https://developers.google.com/style)。

## 句子

- 主语和动词具体：谁做什么、发生什么、下一步是什么。
- 删掉填充：为了、从而、值得注意的是、众所周知、不难发现。
- 少用对冲：可能、或许、一般来说；有证据就直说，没有就标未知。
- 不用谄媚和空泛表扬：很好、强大、优雅、无缝、一站式。
- 一句话只表达一个判断；长句拆开。

## UI 文案

- 按钮说动作；错误说原因和下一步；空态说能做什么。
- 不用技术黑话解释用户问题；不把设计理由写进页面。
- 状态词一致：成功/失败/待处理/未知，不混用。

## 文档与更新日志

- README 回答怎么用；CHANGELOG 回答什么变化、谁需要动作；报告回答如何验证。
- 写用户影响和迁移，不写实现流水账。
- 不编数字、日期、性能收益；没有测量就写未测量。

## 复核

读一遍：读者能否在 30 秒内知道“这是什么、我该做什么、下一步去哪”。不能，就删或改结构。
