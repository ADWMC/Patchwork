# 反 AI 垃圾

- 删空洞形容词（强大/无缝/极致/重新定义）→ 改成可核实收益，或删除。
- 一屏一个主信息；不要并列五个「亮点」。
- 删没有信息的总结与机械铺垫；保留有用的术语、限定和作者声音，不追 AI 检测器分数。
- 汇报写：改了什么、跑了什么命令、结果是什么。不写「完美/应该没问题」。
- 收到用户纠正时先核事实并修正；只有存在真实取舍时才列选项与推荐。
- 按钮写动作（保存草稿）；错误文案必须含发生了什么 + 下一步。

改布局/层次 → `web-ui`。完成证据 → `evidence`。

## 写作与文档的实际流程

先列来自仓库、差异、来源和真实验证的事实，再编辑表达。改前改后核数字/单位、名称、否定、范围、排序、因果、时序、计划/完成、可能/保证和归属；不为“有人味”编造经历、访谈、指标或研究。
摘要、翻译、引文和用户要求保留的原文，不因命中词表就擅自改写。技术/科学限定不能为了简短删除。
README、更新日志和迁移说明的结构与来源核验 → `documentation`（可用时）；本技能只复核表达是否准确、具体且适合读者，不以禁用词表删除技术限定。收录/豁免及收尾规则 → `standards`。
需要直接发送的正文或书页批注，按读者、长度、原文锚点交付可用定稿，不附无关排障材料。
