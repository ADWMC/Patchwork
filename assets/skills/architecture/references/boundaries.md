# 架构边界与依赖

来源参考：[C4 model](https://c4model.com/)、[ADR](https://adr.github.io/)、[Martin Fowler · Architecture](https://martinfowler.com/architecture/)。

## 先问四个问题

1. 谁拥有状态？生命周期和并发由谁控制？
2. 谁调用谁？依赖方向是否指向稳定抽象？
3. 哪些代码会因为同一个原因变化？应放在一起。
4. 哪些部分可以独立替换/验证？边界在哪？

## 判断边界

- 按**变化原因**拆，不按文件长度拆。
- 领域规则放业务模块；入口只组装；桥接只适配。
- 外部依赖通过端口/适配器隔离；不要让数据库、UI 或框架类型泄漏到领域层。
- 共享少量代码不急于抽象；避免 `CommonUtils` 式兜底容器。
- 迁移时同时迁移调用方、配置和测试，不留下两套实现。

## 文档

- C4：Context → Container → Component → Code，按读者选层级，不强制画全。
- ADR：背景、选项、决定、后果、回退点；只对跨模块、难回退或违背既有约定的选择写。
- 图是沟通工具，不是验收证据；用真实调用路径核对。

## 验收

改完沿一条真实入口走通：输入 → 转换 → 副作用 → 输出；确认新边界被实际调用，错误/取消/生命周期有人负责。
