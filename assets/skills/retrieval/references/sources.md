# 来源与停止条件

将一个问题拆成可核主张。每项记录：主张、来源 URL/路径、作者或维护者、版本/日期、实际读取位置、支持/矛盾/未知与适用范围。论文和官方文档优先回答自身方法与契约；产品宣传只能证明宣传内容，不能证明独立性能。

先查最接近事实拥有者的来源。搜索摘要、镜像、旧讨论和二次整理可提示关键词，但不能替代原文。需要当前价格、规则、版本或人物时重新核对发布日期与生效日期。已知来源反驳假设时修正结论，不能只追加支持性搜索。

停止于：已打开的事实拥有者原文直接回答关键主张（无额外交叉核验需求）、重复查询不增加信息、资料不可访问、权限范围禁止继续，或成本超过任务价值。已拿到足够原文时不要继续做同义查询、重开同页或抓取无关页面。凭据、robots、SSRF 或网络失败只记录一次该路径的失败，再按需换可用来源；不要循环调用失败 provider。输出缺口而非猜测；不把搜索结果直接写入长期记忆。检索计数与 token 成本只报告真实测到的数据。

## 最短可用路径

1. 用户已给原始 URL 或仓库路径时，先打开该处；已在当前上下文中完整读过同一版本时，复用已读证据。
2. 不知道原文位置时，搜索用于发现候选。优先事实拥有者、官方规范、版本化源码或原始论文；网页标题和 snippet 只提供线索。
3. 某一网页工具缺凭据或受网络边界拒绝时，不重复同一失败路径。核准官方域名，不能把相似顶级域名视为同源；可试一条版本化仓库或维护者文档的替代路径。单一字段问题至多一次定位查询和一次改写查询；两条原始来源路径都不可达时，停止并报告未核实，不转向无关示例站点、百科或营销页。用户明确要求多来源研究时另定预算。
4. 打开原文后，对照用户问题提取最小支持片段与版本。已足够回答就停止；多来源核验只用于易变、高风险、冲突或用户明确要求的主张。

## 证据包示例

| 字段 | 应记录的内容 |
| --- | --- |
| 问题 | 一个可检验的主张，例如“某规范的 frontmatter 必填字段是什么” |
| 来源 | 实际打开的规范 URL、维护者或版本，而非只给搜索结果页 |
| 支持 | 原文对应小节与字段；相反内容也要保留 |
| 状态 | `verified`、`summary-only`、`stale`、`conflict` 或 `unknown` |
| 限制 | 未打开全文、网络失败、发布日期不明或仅适用于某版本 |

不要因为两处复制了同一段文字就称为独立来源。官方文档与源码矛盾时注明版本和运行对象；新旧资料冲突时核发布日期与生效日期。对单一规范的明确字段问题，已打开该规范的原文通常足够，不需要继续搜十个相近页面。引用只能支撑它实际说出的主张。
