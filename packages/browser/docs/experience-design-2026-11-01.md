# 浏览器标注与操作体验融合

日期：2026-11-01。状态：本轮功能已在本地实现并通过隔离验证；未发布、未安装到主 DSH。版本仍为未发布的 `0.2.0`。

用户目标：把截图中的 Annotate 融入独立可选浏览器包，并吸收 ZCode 浏览器操作工具与技能中可改善实际使用的机制。继续采用 DSH 侧栏画面流，不改主 DSH，也不把浏览器重新并入 Patchwork。

## 本轮交付范围

1. 标注模式：点击选择元素、拖动选择区域、添加说明与编号；按住 Space 临时操作网页，Esc 取消；默认不把标注行为点击到网页上。
2. 标注与实际页面身份绑定；导航、标签和视口变化时拒绝旧目标。用户写下的说明与网页内容分开，不把网页文字当作授权。
3. 用户可将选定标注交给当前已授权 Agent 读取，未提交草稿不进入模型上下文；不会向其他会话发布。
4. 对照 ZCode 固定提交中的浏览器工具、能力清单和两个 skill，设计独立按需浏览器技能与能力映射；不复制它的 Electron 载体或共享登录分区。
5. 评估少步骤、高频的体验改进，分别标明本轮实现和后续项。最终用隔离注册表与真实浏览器验证，不以静态按钮或模型口头完成代替证据。

## 已实现的操作闭环

1. 用户点导航栏“标注”，浏览器先转为用户接管。点击元素获取边界与摘要，拖动获取区域，均保存当时实际 PNG；该动作不会点击网页按钮。
2. 编号框与反馈面板显示在浏览器工作台。编辑每条说明，可折叠、移除、继续选择；说明、调试提示不会写入被访问页面的 DOM 或交付 HTML。
3. Space 按住期间透传真实页面操作，松开恢复标注，窗口失焦也会解除透传；输入说明时空格正常输入，Esc 退出选区模式。
4. “发给当前 Agent”先提交草稿，再经 `ctx.sessions.scope(sessionId).get('conversation').send(text)` 发往绑定会话。宿主不提供此能力时明确显示“提交标注”，不会假装消息已发出。
5. 发送失败保留已提交标注，“重试发送”只重发说明、不重复创建标注；新草稿清理旧成功提示。投递确认丢失时仍可能发生重复消息，当前没有宿主级幂等消息回执，不能承诺 exactly-once。
6. Agent 使用 `annotations` 读取已提交反馈；只有需要看图时再传 `annotationId`。提交和发送不会恢复自动控制，底栏“恢复 Agent”由用户决定。
7. 导航、切换标签、调整视口或页面操作会使旧选区失效。提交前还核对页面观察指纹；旧图可解释历史反馈，不能直接变成当前点击目标。

### 工具与技能

- `open`：只复用完全相同 URL；同站的其他页面新建标签。打开已存在页面只选中，不刷新。
- `check`：通过实际观察到的唯一语义目标设置 `checked`，避免把开关点击反。
- `selectOption`：选择实际 option value。快照额外提供有界选项列表：最多 12 个 select、各 30 个 option，文本摘要最多 4000 字符，总快照仍为 16000 字符。未返回的值不得猜测。
- `browser-workspace`：与工具注册到同一 Agent 原生作用域；主文件放操作原则，`references/operations.md` 放真实工具例子，`references/gui-verification.md` 放页面验收。无 `skills` 宿主服务时工具仍可用，但不假设 skill 已注册。
- Ctrl/Cmd+L/T/W/R：仅面板获得焦点时分别定位地址、新建、关闭、刷新。其他宿主区域不接管快捷键；标注模式也不全局监听 Space。

### 隔离与有界上下文

草稿不进入 Agent 工具结果，已提交说明也不注册成全局提示词。`annotations` 只返回当前授权实例的数据；其他会话、新授权或切换后的 Agent 不能访问旧 id。工具枚举不包含创建／提交／删除标注等用户面板操作。模式变化撤销工具与技能；注册中途失败也回滚已经注册的部分。

每实例最多 8 个标注、每条 600 字、单图 2 MiB、图像总计 8 MiB；只有按需调用才交付图片。草稿和裁图不持久化，不写入长期记忆；撤权／销毁时清空内存。说明输入缓存随移除清理。宿主附件存储在图片真正被读取后拥有自己的文件生命周期；不能将浏览器清空等同于删除会话附件或聊天记录。

标注与当前 page、generation、frame、viewport 和采集指纹绑定；异步截图和图片提交后复核授权，撤权期间的未完成请求返回 403。网页中的文字始终视为不可信内容，不因为被框选就升级为用户授权。

## 下一批明显改善体验的功能

这些是设计项，尚未伪装成已支持。继续归属 `@patchwork/browser`，不把依赖重新塞入主包。

| 优先级 | 功能 | 体验收益与验收条件 |
| --- | --- | --- |
| P1 | 悬停元素轮廓、父级切换与小面包屑 | 点之前知道将选哪个组件；只能定位当下有身份的 DOM，滚动／导航立即失效；跨域 iframe 明确降级框选 |
| P1 | 标注处理状态与前后对比 | Agent 可提出“已修改”，用户看同位置的前后截图并确认；不把模型自报完成直接标成通过 |
| P1 | 关闭标签撤销／Ctrl+Shift+T | 误关闭可恢复网址；历史最多 10 项，仅本会话，明确不保证未提交表单和 JS 内存 |
| P1 | 加载进度、停止加载与错误恢复 | 地址切换有反馈，慢站可停止；失败保留地址与原因，避免用户连点造成重复标签／提交 |
| P2 | 只读控制台和网络失败摘要 | 页面出错时按需显示有界错误，不把大量日志送入每轮上下文；过滤 Cookie、Authorization 与请求体 |
| P2 | 页面交付与固定预览标签 | 区分临时查阅和最终预览，任务完成保留交付页；用户固定的页不自动回收，仍受本会话资源预算 |
| P2 | 文件传输进度与可见结果 | 显示授权目标、进度、真实路径与失败原因；不把“已发起下载”当作“文件已保存” |

P1 的实施顺序：先补元素选择精度，再加关闭撤销和加载反馈，最后做标注前后对比闭环。每项沿用当前真实浏览器与隔离回归；引入新能力时同步更新工具 schema、capabilities、skill 和 changelog。

## 验证与限制

机器结果见证据清单。本轮使用私有 Edge 与私有 Playwright 查看端；Browser 插件不可用，因此采用该回退路径，没有连接宿主浏览器。

- 全仓测试 308 项通过、0 失败、0 跳过；包含原生 DSH/Cordis scope 的 skill 注册、撤销与会话隔离，以及标注原子提交、撤权竞争、图片边界、会话消息绑定和注册失败回滚。
- 真实浏览器经原生 DSH 工具注册表完成开关／输入／选择、URL 精确复用、点击标注不触发网页、Space 真实点击、框选、发送失败重试和其他会话不可读。
- 采用 DSH 原生 attachment-local 存储实际裁图，经解码、尺寸与 SHA-256 校验后读回；本次样例为 164 × 94、3036 字节的 PNG。
- 1264／900／380／320 像素与浅深色有渲染检查；380／320 像素展开标注面板不横向溢出，保留可操作网页区。已实际查看桌面和窄屏截图。
- 消息发送采用绑定会话的捕获回调验证，并对原生 scoped conversation 调用方式做单元验证；**没有在完整 DSH 客户端中触发真实模型处理标注**，模型请求为 0，不能称为完整模型端到端验收。

目前点选识别顶层文档和开放 Shadow DOM；跨域 iframe 内部只可用区域表达，不能承诺识别其内部语义元素。ARIA 指纹不等同于完整视觉布局快照，纯 CSS／动画变化可能不触发同样的失效判断；裁图是采集时的实际页面，模型处理前仍须重新观察。标注不是自动修改网页代码的工具。

可选包继续独立构建与 `npm pack`，不包含浏览器内核、录像二进制或测试截图。未发布 npm，未改主 DSH 配置，未替换此前仍在使用的预览服务。
