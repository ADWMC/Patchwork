# 浏览器性能与操作能力改进方案

日期：2026-11-01。状态：三阶段核心改造已实施并通过隔离功能验收；长稳、跨平台和完整桌面能力仍未验收，详见末尾执行记录。范围为独立可选包 `@patchwork/browser`，延续现有 DSH 画面流路线，不修改主 DSH 或用户宿主浏览器。前文诊断数据保留为改造前基线，不代表当前实现。

## 已确认的结构问题

1. `src/browser/route.mjs` 以固定 150ms 定时器发送最新画面：该传输层理论上限约 6.7 帧/秒；JPEG 回退再受客户端 800ms 轮询和截图耗时限制。这是代码限速，不是实测平均帧率。
2. `src/client/BrowserPanel.jsx` 把每个字符、滚轮事件放入同一串行队列。每个操作还等待服务端响应以及完整状态／画面刷新，后续输入必须等待前一个完成。
3. `src/browser/session.mjs` 对普通用户输入也执行前后 ARIA 观察；`result()` 再读取档案、后端和录像器等完整状态。人工打字、滚动没有必要逐次走 Agent 任务验收链。
4. 点击、滚动等普通操作调用 `invalidate()`，其实现连同画面流一起停止；导航保护、观察失效、标注过期和传输重连混在同一个代次里。客户端还存在重连等待与静止 3 秒后主动断流逻辑。
5. 每帧走 base64 → JSON/SSE → atob → 字节数组 → Blob → Object URL，并更新整个面板的 React 状态。接收的部分帧最终又被服务器丢弃，存在重复搬运与渲染开销。
6. 当前画面主要提供左键单击、纵向滚动和按键转发，没有完整的 down/move/up、拖拽、双击、右键与横向滚动协议。已经存在用户主动纯文本粘贴和 `onCompositionEnd` 转发，不能当成完全缺失；但焦点目标是不可编辑的 `img`，直接中文输入法是否稳定工作尚未验证，目前另有文字输入条。固定视口图像被缩到侧栏，内容小、点击难。

这些问题足以解释“操作迟钝、输入排队、画面断续、功能不够用”；页面网络、内核启动、指纹噪声与 GPU 开销仍需分别量测，不能直接归咎于 AliasMode。

## 一次性隔离实测

2026-11-01 使用正式安装的 AliasMode Chromium `155.0.8059.85`，通过现有 `BrowserSession` 启动独立 headless 进程，临时档案不保存登录。页面由 `setContent()` 构造，包含一个输入框、动画及 10／2000 行文字和按钮；分别串行输入 12 个字符。计时不包含启动与组件完整性校验，也不包含 HTTP、SSE、前端刷新与实际显示时间。

| 页面 | 直接调用内核输入：12 字符总耗时 | 当前 Session 输入：12 字符总耗时 | Session 单次中位耗时 | 12 次输入触发 ARIA 观察／完整状态读取 |
| --- | ---: | ---: | ---: | ---: |
| 10 行 | 10.8 ms | 150.1 ms | 12.9 ms | 24／12 |
| 2000 行 | 38.2 ms | 2486.6 ms | 204.8 ms | 24／12 |

两组最终文字均与输入完全一致；独立流订阅在执行一次普通 `scroll` 后触发了 `onEnd`，复现断流。这里没有测量侧栏端到端帧率，不能把内核产生的帧数当作用户看到的 FPS。

边界：单机、每种页面单轮 12 字符、小样本；直接输入是诊断对照，不是已经可用于生产的安全输入路径。计数包装保留原调用结果，Session 的组件状态查询针对临时数据根目录，不能代替正式实例的全部磁盘开销。测试页无外部网络与真实站点负载，尚未量测内存、GPU、跨网络、长期运行与 DSH 界面延迟。探针 finally 关闭独立浏览器并删除临时目录；未启动预览服务、改写主 DSH 或导入宿主浏览器资料。

## 技术路线与兼容边界

- 保留“真实独立 Chromium + DSH 内画面”的路线；卡顿优先修输入、代次和显示链路。ZCode 既有研究说明它的 Desktop 显示使用 Electron `webview`，不能直接搬到普通网页容器；复用它的用户接管与浏览器操作方式，不引入整套 Electron。参见仓库 `docs/zcode-browser-research-2026-11-01.md`。
- 本地 DSH 源码 `packages/host/webserver/src/index.ts` 已有 `WebUpgradeRoute` 和 `webServer.registerUpgrade()`，路由拥有升级握手与 socket 生命周期。可以在可选包中增加二进制 WebSocket 传输，无须修改主 DSH。此结论仅针对当前检出的宿主源码，部署时仍须运行时探测；旧宿主保留优化后的已鉴权流式 fetch/SSE。
- 浏览器原生 WebSocket 无法沿用 fetch 的任意鉴权请求头。通过现有鉴权 HTTP 请求签发短时、一次性、绑定 session／accessId 的连接票据，在升级连接后首条消息验证，未验证前不订阅画面；禁止把长期凭据放入 URL。票据不写磁盘，首次认证有超时，连接检查 Origin、帧大小与消息速率，撤权主动关闭。若宿主鉴权契约不满足，则保持 SSE，不自行开未鉴权端口。
- 不开放原始 CDP socket 或任意方法调用给网页／Agent。用户输入使用有类型、有尺寸与代次校验的指令；Agent 继续使用受限工具与必要观察。新连接仍绑定当前已授权会话及其浏览器，不共享其他会话的档案、画面或输入。

## 实施顺序

### 第一阶段：先修操作热路径

- 用户输入独立为轻量通道：校验会话授权／控制权／标签／文档与视口代次 → 应用输入 → 有界确认；不逐字符做 ARIA、全量状态读取或等待截图。
- 保留输入顺序与下压／释放配对；滚动增量和鼠标移动合并，只保留最新移动，不能丢弃点击、释放、Enter 或已提交文字。队列有上限与取消机制，切会话立即失效。
- 拆分文档／视口代次、帧序号、Agent 观察 revision 和标注 revision。普通点击／滚动使观察或标注过期，但不中断仍有效的同页画面流；导航、切标签、换环境、撤权仍立即销毁旧能力。
- 输入完成由序号确认，画面独立更新。手动点击接管仍立即生效，Agent 在下一写操作检查点停止。队列状态区分等待、已执行和被取消，不能用全局 busy 阻止用户继续输入。静止页面不按“3 秒没新帧”判断失联；改用连接心跳和明确错误。
- 状态按变化推送或按 revision 拉取，环境与组件信息缓存并明确失效条件，不在每次键入后重新遍历磁盘。

### 第二阶段：改善显示与输入能力

- 显示层只保留最新帧，独立于工具栏 React 更新；按浏览器渲染节奏绘制，限制排队解码，避免越看越延迟。
- 先去掉固定 150ms 发帧瓶颈，采用受背压约束的自适应发送；随后在宿主支持时增加二进制 WebSocket。第一版不引入 WebRTC、音视频转码或另一套浏览器内核；二进制只减少搬运，不承诺自动解决所有延迟。保留已鉴权的 JPEG 回退。
- 使用专用可编辑输入代理承接输入法组合，组合期间不重复提交，commit 后一次发送；保留现有主动粘贴并验证中文、换行与长度边界。完整转发 pointer 按下／移动／释放、双击、右键和横向滚动；失焦、断连、切页释放远端按键与按钮，避免拖拽卡住。文本选择发生在远端页面，复制到本地需由用户明确触发且遵守浏览器剪贴板权限，不后台读取系统剪贴板。
- 提供等比适配、100%／缩放和平移，以及更大的工作区视图。显示缩放与真实网页 viewport 分开，避免为了放大面板改变指纹环境。大视图先在插件根容器提供可退出的扩大模式，并探测 Fullscreen API；DSH 独立工作区／主标签公开入口尚未确认，不能预先承诺。圆角、颜色和控件沿用 DSH tokens，工具栏不在页面画面中叠说明文字。

能力边界：CDP 网页画面不等于完整桌面窗口。系统文件选择器、浏览器原生菜单和某些权限弹窗不能假设会进入画面流。网页自己的 DOM 菜单按远端操作验证；打开链接、复制地址、上传等常用原生操作通过插件内有权限边界的控件承接，并明确标记暂不支持的项目。这里不承诺与桌面 Chrome 的全部 UI 等价。

第一阶段主要涉及 `src/browser/session.mjs`、`stream.mjs`、`route.mjs` 和 `src/client/BrowserPanel.jsx`；第二阶段把输入协议和画面显示拆为独立模块，再扩展客户端与包内技能。既有观察、标注和回执校验不是整体删除：只移出人工输入的逐字符热路径，Agent 仍保留必要前置观察、结果检查与可审计操作记录。

### 第三阶段：增强能力与搜索桥接

- 导航可取消，加载状态、失败重试和恢复网址明确；上传、下载、页面弹窗等有独立能力状态，不让不支持的动作静默失效。
- 自动搜索保留轻量 HTTP 路径；动态页面读取按需接入当前已授权浏览器的独立搜索标签，受 host／robots／SSRF、超时、并发和结果长度边界约束，不借浏览器绕过既有拒绝。
- 更换指纹、代理、保存登录与资源回收保持独立。未经同条件测试，不通过关闭 sandbox、禁用指纹保护或删除校验来换取速度。

## 验收目标与发布顺序

以下是本地回环、1280×800、前台可见、未录像条件下的验收目标，不是所有项目均已达到的声明。完整性能评估仍需硬件、CPU/GPU、冷／热启动及每项至少三轮数据；本轮实际覆盖和未覆盖项目见执行记录。简单页、2000 行页、真实表单与长页分组，不把网页自身渲染和网络耗时隐藏在平均数里。

| 项目 | 目标／通过条件 |
| --- | --- |
| 输入协议确认 | 每组至少 100 次提交，单次 P95 ≤80 ms；另报排队等待时间，禁止仅统计出队后的执行时间 |
| 输入到可见变化 | 本地确定性输入页 P95 ≤200 ms；端到端从 UI 事件到对应画面显示，不能以服务端 ACK 代替 |
| 连续文字 | 一次提交 100 字符后 ≤300 ms 完整落入页面；快速逐字输入、中文组合与粘贴无丢字、重复、乱序 |
| 滚动画面 | 首先达到有效呈现 ≥15 FPS，余量允许时再向 30 FPS 调节；统计重复／丢弃帧与输入到显示的帧龄，不能只报接收帧数 |
| 队列与恢复 | 移动／滚动有界合并；点击／释放不丢；2 秒连续滚动停止后 ≤200 ms 清空待执行输入，静止 60 秒不因无新帧反复重连 |
| 完整操作 | 验证拖动滑块、拖拽选择文本、双击、右键、横向滚动、中文输入、主动复制／粘贴、上传与下载；说明网页自身禁止的动作 |
| 生命周期 | 导航、切标签、切会话、隐藏、失焦、撤权、换环境均验证；旧文档坐标与旧授权立即拒绝，无卡键、残留查看者与跨会话显示 |
| 资源 | 30 分钟操作后，收尾空闲的内存与解码队列不持续增长；报告绝对 RSS、私有浏览器进程数与不同内容阶段峰值，不能只报平均数 |
| 回退 | 禁用 upgrade 接口／断开流后可回到已鉴权 SSE／JPEG；状态准确，无重连风暴；按后端分别标明支持能力 |

实施拆三次可审查交付：第一阶段验证去除逐字符观察与滚动断流；第二阶段验证显示和操作完整性；第三阶段再交付搜索与更多页面能力。每次分别更新测试、能力说明和实际已完成的 CHANGELOG。第一阶段未通过端到端与隔离回归，不以“换成 WebSocket”宣告完成。

包内保留兼容旧动作和旧传输的显式回退开关，但不能同时向两个输入路径重放同一动作。超时后只报告未知或查询序号结果，不自动重发点击／提交等非幂等动作。先将新路径用于一次性隔离实例，验证后才在该独立包中切默认；不改主 DSH 安装、不使用用户宿主标签、不留下常驻调试服务。

## 源码定位

- `packages/browser/src/client/BrowserPanel.jsx`：`act`、`input`、`refresh`、轮询、键盘／粘贴／组合输入与图像显示。
- `packages/browser/src/client/browser-stream.mjs`：二进制流与 SSE 解析、显示确认。
- `packages/browser/src/browser/route.mjs`：HTTP 鉴权、轻量输入、票据与回退传输。
- `packages/browser/src/browser/transport.mjs`：WebSocket 首消息认证、一次性票据、latest-only 与显示 ACK。
- `packages/browser/src/browser/input.mjs`、`src/client/input-queue.mjs`：输入序号、边界与合并。
- `packages/browser/src/client/BrowserFrame.jsx`：独立图像解码和 DOM 生命周期。
- `packages/browser/src/browser/agent-features.mjs`：紧凑引用、限长读取与条件等待。
- `packages/browser/src/browser/public-network.mjs`：检索临时认证代理和已校验 DNS 地址连接。
- `packages/browser/src/browser/session.mjs`：`action`、`result`、`status`、`invalidate`、焦点及画面代次。
- `packages/browser/src/browser/evidence.mjs`：`observation` 的 body ARIA 快照。
- `packages/browser/src/browser/stream.mjs`：CDP 画面订阅、每帧处理与代次绑定。
- 相邻 DSH 源码 `../deepseek-harness/packages/host/webserver/src/index.ts`：`WebUpgradeRoute`、`registerUpgrade`；当前源码存在接口不等于所有已安装版本均支持。

## 执行记录：2026-11-01

三阶段的输入热路径、二进制画面流、操作补齐、Agent 工具与显式浏览器检索均已落到源码和构建产物。第三阶段实际采用临时空登录上下文，替代前文候选的独立搜索标签，避免改变用户的可见标签和登录。主包只持有按实际 Agent 实例绑定的可选能力桥接，浏览器及其依赖仍单独安装。社区来源与逐项取舍见 [Agent／UX 融合记录](community-agent-ux-2026-11-01.md)。

最终机器记录：[公网与交互验收 JSON](checks/interaction-public-2026-11-01.json)。环境为 Windows、AMD Ryzen 9 7945HX、AliasMode Chromium `155.0.8059.85`、1280×800 的 2000 行页面；真实 DSH 工具注册表与执行、真实 DSH 主题和控件，在独立 Playwright 查看上下文运行 React StrictMode 面板。没有使用宿主浏览器、没有修改主 DSH；不是完整 DSH 应用壳，模型请求数为 0。

扩展到 100 次输入后曾暴露 P95 300.3 ms 与 1.8 FPS，发现显式接管会终止二进制流，且旧连接结束回调可能覆盖新连接状态。已修复控制权切换的失效范围与连接代次；最终验收断言输入 P95 ≤200 ms、显示 ≥15 FPS、正常操作零次断流。早期 12 字符诊断和最终端到端测量口径不同，不能据此直接计算提速倍数。

已验证：真实工具 schema／execute、refs 与过期拒绝、3 步表单 batch、read／wait／hover／scrollTo、文字／合成 IME／粘贴、拖动滑块、双击、横向滚轮、扩大／Escape、100% 显示缩放、暗色 token、取消导航、SSE 回退、旧坐标拒绝、未授权会话无工具并清屏，以及检索隔离、预算拒绝、取消和接管。

尚未完成上表全部目标：三轮同条件性能统计、独立输入 ACK P95、100 字符／队列清空专项计时、静止 60 秒（本轮 3.5 秒）、30 分钟内存／GPU 长稳、真实 Windows IME、系统原生菜单／文件选择器、跨平台及反自动化站点覆盖。本轮也不代表完整 SSRF／DNS／重定向对抗审计；原 HTTP／robots 请求仍沿用既有实现。Camoufox 与 SOCKS 检索代理暂不支持，手动浏览保持原能力。

复现方式（仓库根目录，PowerShell；路径均需显式指定到隔离目录）：

```powershell
pnpm test
node packages/browser/tests/interaction.acceptance.mjs --component-root C:/path/to/isolated/patchwork/browser --dsh-source C:/path/to/deepseek-harness --output C:/path/to/interaction.json --public-url https://example.com/ --public-proxy http://127.0.0.1:7897
```
