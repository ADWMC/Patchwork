# 指纹更换：入口、行为与实际生效边界

日期：2026-11-01。属于独立可选包 `@patchwork/browser`，本地实现、未发布；不修改主 DSH 或宿主浏览器。

后续已新增独立 AliasMode 原生内核路线，实际更换与重启通过验收，见[原生指纹执行记录](native-fingerprint-2026-11-01.md)。本页保留此前设备模板／JS 样本验证的历史范围；“尚未验证完整指纹注入”只针对这里的 JS 路径，不代表后续原生路径未运行。

## 原有缺口

指纹功能没有在拆包时删除，但此前入口藏在更多菜单的“浏览器环境”中。可以新增／切换环境，却没有直接重新生成身份的操作，也没有在环境列表展示样本要求的内核版本。调整语言会保留原硬件样本，本来就不等于换一套指纹。

## 本次实现

顶部标签栏右侧增加“指纹”，菜单中的入口改为“环境与指纹”。管理区展示当前模式、实际运行内核、环境列表及设备参数／指纹 ID。完整指纹显示样本 Chromium 主版本；已知同后端实际内核不匹配时，“使用”和选择项均不可用，并显示原因。服务端继续执行最终兼容检查，不能靠绕过 UI 启用。

更换流程是 `更换设备参数／更换指纹 → 生成新环境 → 使用`：

1. 用户确认生成后，后端在当前会话的档案锁及 revision CAS 下创建新环境，不修改正在运行的源环境。
2. 设备模式重新采样屏幕／DPR；完整模式重新生成样本。最多尝试 8 次，必须与源身份 ID 不同；相同样本、生成失败、容量超限、外会话引用或过期 revision 都不会被记为成功。
3. 新环境获得独立 UUID 和存储命名空间，不复制旧 Cookie、localStorage、IndexedDB；沿用语言、时区、代理等配置。沿用“保存登录”的开关只是允许以后保存，不表示复制旧登录。
4. 生成成功保持当前标签和源环境；用户点击新环境“使用”才会切换，切换会关闭旧标签。当前已有 context 时先验证新 context，再移除旧页面；验证失败保留原页。
5. 原生环境保留真实浏览器身份，没有虚假的“随机硬件”按钮；用户可以新增设备模板或完整指纹环境。

`regenerateProfile` 仅属于用户面板动作，不在 Agent 工具枚举中。所有配置、登录与切换仍按实际 Agent／会话授权隔离，其他会话无法访问该档案。自定义环境上限仍为 8，没有增加新依赖。

## 必须区分的能力

| 模式 | 实际作用 | 当前验证边界 |
| --- | --- | --- |
| 原生 | 使用真实引擎与设备身份 | 没有承诺改变硬件／网络身份 |
| 设备参数模板 | 语言、时区、屏幕、视口、DPR 等配置；更换重新采样屏幕／DPR | 真实浏览器已通过 UI 完成生成、切换与参数变化检查；不等于改变 CPU、GPU、Canvas 或出口 IP |
| 完整指纹（实验） | 保存完整生成样本，支持生成另一套样本；兼容版本下进入现有注入路径 | 当前实测系统内核 Chromium 156，与生成样本主版本不一致；验证的是明确拒绝启用并保留原页，**尚未验证实际完整指纹注入** |

ID 是配置身份摘要，不是浏览器已经生效或站点反检测通过的证明。下次完善完整模式时，应先对齐生成器支持范围和独立可选内核，再核对 HTTP/JS UA、screen、DPR、Canvas、WebGL、iframe 等实际观测；不能为了显示成功而绕过主版本检查。Camoufox 也不能直接使用 Chromium 样本。

本轮复测还发现导航自动调用 `setViewportSize` 会重置 `screen`，这是 [Playwright 官方明确说明的行为](https://playwright.dev/docs/api/class-page#page-set-viewport-size)。现已改为仅原生模式导航时自动适配；设备／完整指纹环境保留创建时的视口，不再每次导航都覆盖屏幕参数。用户显式“适配侧栏宽度”或 Agent 的 `resize` 仍会调整视口，设备模板的 screen 可能随该 API 改变；需固定设备参数时保留档案视口，响应式宽度测试优先使用原生环境。本轮没有通过自造 getter 把变化伪装成稳定硬件。

## 验证

机器结果与脚本／截图哈希见 [fingerprint-switching-2026-11-01.json](checks/fingerprint-switching-2026-11-01.json)。

- 全仓 311 项测试通过，0 失败、0 跳过。新增覆盖不同样本、源档案在使用中的安全生成、旧登录保留与新登录为空、相同样本拒绝、CAS、外档案拒绝和 Agent 无权更换。
- 真实原生 DSH/Cordis 工具注册表与两个私有 Edge 实例，实际 GUI 完成设备环境创建、使用、生成替代环境、保留原页后显式切换。以只读页面观测验证实际屏幕／DPR，不以 ID 变化代替生效证据。
- 登录标记只在测试准备阶段种入源浏览器。正式检查通过 GUI 切换后，读取新 context 的 Cookie 与 localStorage 确认均为空；没有用直接改 store 伪造切换结果。
- 完整指纹实际生成了不同 ID；版本不兼容时 UI 阻止启用，直接用户路由也被拒绝，旧页面保留。没有宣称运行了完整注入、站点匿名性测试或 ZCode 对照。
- 900／380／320 像素及浅深色检查管理面板无横向溢出；已查看桌面和窄屏截图。原标注、Space、截图、工具／技能隔离与撤权检查一并回归。
- Browser 插件不可用，使用私有 Playwright 查看端；不操作用户现有浏览器，不修改主 DSH，模型请求为 0。完整 DSH 客户端中的模型回合仍不在此项验收范围。

本轮只打包本地可选包，不自动安装新内核、不发布 npm，也不自动把用户当前页面切换为新身份。
