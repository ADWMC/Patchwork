# GUI 验收

根据用户问题选择必要覆盖面：主流程、错误反馈、边界输入；视觉问题再加相关视口与主题，不对每次普通查询强制截图整页。

准备阶段可以启动本地服务、建立测试账号和数据。正式验收通过界面的真实点击、输入、选择和滚动触发目标行为；不可直接改 DOM、localStorage、应用 store 或发后台请求替代被测操作。只读 DOM 与状态检查可作为证据。

每个检查写清动作和预期变化，再取得对应观察。DOM 能回答选中态时不必重复发大图；布局、颜色、遮挡、动画反馈需要真正查看截图。截图存在但未查看不能叫视觉通过。短暂反馈可取动作前后两张，不能用任意等待冒充状态出现。

出现问题先区分页面缺陷、目标失效、权限和能力缺失。保持失败现场，记录复现与实际表现；不通过强制点击、改存储或刷新逃离失败后宣称通过。重置测试数据须明确重开该检查。

`capabilities` 和工具实际返回决定可做什么。登录、上传、下载、录像或环境安装可能要求用户面板操作，不伪造成功。末尾报告通过／失败／未测及对应证据；控制台和跨域能力未提供就如实说明，浏览器自检不等于站点反检测或完整安全验收。
